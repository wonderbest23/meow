노트북을 닫고 나가기 전 핸드오프를 한다. 클라우드 세션(휴대폰 Claude 앱)이 이 저장소만 보고 바로 이어서 일할 수 있게 하는 것이 목적이다.
사장님이 남긴 메모: $ARGUMENTS

아래 순서대로 하고, 중간에 확인이 필요한 일만 묻는다.

## 1. 상태 보기
- `git status`, 지금 브랜치, `git log --oneline origin/main..HEAD`, 커밋 안 한 변경을 확인한다.
- 이 세션에서 한 일, 사장님이 내린 결정, 돌린 시험·0원 점검 결과를 대화에서 정리해 둔다.

## 2. 브랜치 정하기
- 지금 브랜치가 `main`이거나 브랜치가 없으면 `handoff/<YYYY-MM-DD>-<한두 단어 영문 주제>` 브랜치를 새로 만든다. main 에는 절대 커밋·푸시하지 않는다.
- 이미 작업 브랜치에 있으면 그 브랜치를 쓴다. 강제 푸시(`--force`)와 히스토리 고쳐 쓰기는 하지 않는다.

## 3. 비밀값 막기
- `.env*`, `.dev.vars`, 키 파일, `*.pem` 은 커밋하지 않는다.
- 올릴 변경(`git diff` + 새 파일)에 API 키·토큰·비밀번호·카드/계좌번호·손님 개인정보처럼 보이는 값이 있으면 멈추고 사장님께 어떤 파일의 어느 줄인지 알린다.

## 4. 빠른 점검(막지 않는다)
- `npx tsc --noEmit -p .` 를 한 번 돌린다. 실패해도 핸드오프는 계속하고, 실패 내용을 HANDOFF.md 의 '하다 만 것'에 적는다.

## 5. HANDOFF.md 에 남기기
- 맨 위 제목·안내 바로 아래, 다른 기록보다 위에 새 절을 넣는다(최신이 위). 맨 위 `최종 정리:` 날짜도 오늘로 바꾼다.
- 형식(짧게, 사실만, 한국어):

```
### <YYYY-MM-DD HH:MM> KST 핸드오프 — 브랜치 `<브랜치>`

- 이번에 한 일: <PR 번호·커밋과 한 줄 설명>
- 사장님 결정: <정한 것과 이유>
- 점검 결과: <돌린 시험·0원 시뮬레이션 명령, 시험 사업, 점수/통과 여부>
- 하다 만 것: <파일·상태, 실패 중인 시험>
- 다음에 할 일: 1) … 2) …
- 노트북이 있어야 하는 일: <비밀값 입력, wrangler, Lightsail, 로컬 Supabase 등 — 없으면 '없음'>
- 메모: <$ARGUMENTS, 없으면 생략>
- 이어서 하기: 클라우드 세션에 「HANDOFF.md 읽고 `<브랜치>` 브랜치에서 이어서 해 줘」
```

- 비밀값·키·개인정보는 쓰지 않는다. 지난 기록은 지우거나 고치지 않는다.

## 6. 커밋·푸시
- 바뀐 파일과 HANDOFF.md 를 함께 커밋한다. 메시지: `핸드오프: <한 줄 요약>` (아직 덜 된 작업이면 앞에 `WIP `).
- `git push -u origin <브랜치>`. 네트워크 오류면 2·4·8·16초 간격으로 네 번까지 다시 시도한다.
- 병합·배포·PR 병합은 하지 않는다(열려 있는 PR 이 있으면 번호만 알린다).

## 7. 마지막 답(사장님께, 한국어, 짧게)
- 푸시한 브랜치 이름과 커밋
- 휴대폰에서 붙여 넣을 한 줄: 「HANDOFF.md 읽고 `<브랜치>` 브랜치에서 이어서 해 줘」
- 노트북이 있어야 하는 일(있으면)
- 비밀값 때문에 멈춘 것이 있으면 그것부터
