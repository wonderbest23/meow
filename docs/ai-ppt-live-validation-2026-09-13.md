## 내용과 화면 확인

운영 분석은 동일한 7일의 문의 3→5건, 주문 0→1건, 매출 0→50,000원, 지출 5,000→10,000원을 비교했다. 증감과 원인을 구분했고 자료가 적어 인과관계나 지속적인 성과를 단정할 수 없다는 제한을 포함했다. 원인 가설은 입력 수치에 연결된 근거 ID를 보유한다.

PPT는 별도의 가상 창업 사업안이다. 소개글 3개/수정 1회/시범 가격 5만원/예산 20만원/주 5시간/월 최대 2건이라는 입력 조건을 보존했고, 월 2건은 판매 실적이나 목표가 아닌 수용 상한으로 표시했다. 전 슬라이드의 출처가 실제 입력 항목에 연결되며 발표자 노트에도 남아 있다.

9장 전부를 1920×1080 PNG로 렌더링해 개별 확인했다. 이 표본에서 한글 깨짐, 글자 겹침, 텍스트 잘림은 발견되지 않았다. 가장 긴 수치인 `월 최대 2건`은 두 줄로 정상 표시됐다. 기하 검사에서 나온 11개 경계 경고는 화면 밖으로 잘리는 기존 배경 도형이며 텍스트가 아니다.

사용한 뷰어는 Artifact Tool 렌더러다. Microsoft PowerPoint나 Google Slides 앱에서 직접 열어본 검증은 아니다. 한 표본의 통과가 모든 업종/문장 길이/출력 형식의 품질을 보장하지 않는다.

## 발견한 문제와 수정

PptxGenJS가 실제 파일에 없는 `slideMaster2.xml`부터 `slideMaster9.xml`까지 콘텐츠 유형 목록에 선언했다. 최초 PPTX 구조 검사에서 누락 참조 8개를 확인했다.

`lib/plan-builder/deck-render.ts`에서 ZIP 내부 XML을 파서로 읽고, 실제 파일이 없는 슬라이드 마스터 선언만 제거한다. 실제 마스터와 모든 슬라이드/발표자 노트는 보존한다. `scripts/deck-job.test.ts`에 선언된 파일의 존재 여부와 노트 보존 검사를 추가했다.

수정 후 결과:

- PPTX 패키지 무결성 검사: 문제 0개
- 슬라이드 수/16:9 비율/제목·목록 기하 검사: 결함 0개
- 수정 전후 렌더 이미지: 9장 모두 픽셀 동일
- ZIP 내부 변경: 콘텐츠 유형 목록과 재생성 시각 메타데이터만 변경

## 저장 결과 재사용

실제 분석 결과, PPT 초안, 검토 완료 구성을 저장한 뒤 다른 프로세스에서 다시 실행했다. 이 재실행은 실키 대신 오프라인용 값을 쓰고 모든 네트워크 호출을 차단했다. 저장된 결과만으로 수정된 PPTX를 만들었으며 누적 실제 API 호출은 3건 그대로였다.

이는 로컬 파일 체크포인트 재사용 검증이다. Google 로그인 후 복원이나 브라우저 재접속 다운로드 검증으로 해석하면 안 된다.

후속으로 로컬 Auth/PostgreSQL/HTTP에서 같은 완료 구성을 가져와 이메일 로그인 전후 이전, 결제 상태별 권한, 새 세션 재로그인 및 토큰 갱신 후 실제 PPT 다운로드 15개 항목을 통과했다. 추가 AI 호출은 없었다. [인증된 다운로드 검증](./local-deck-download-2026-09-13.md)에 별도 기록했으며 Google/PG/브라우저 UI/Cloudflare 검증을 대체하지 않는다.
