# 출시 검증 현황

최신 종합 결과는 [2026-09-14 최종 로컬 검증과 출시 판단](./release-readiness-2026-09-14.md)에 정리했다. 아래 내용은 9월 13일의 검증 기록이며 이후 B2B 제안서와 문서 갱신 변경을 모두 포함하지 않는다.

기준: 2026-09-13 로컬 작업본. 운영 서버의 배포 상태와 같다고 가정하지 않는다.

## 현재 판단

로컬 기능 연결과 안전성 검증은 진행됐지만, **유료 정식 출시 승인은 아직 보류**다.
실제 AI 개선 분석과 9장 PPT 생성은 가상 사업 1건으로 통과했다. 로컬 이메일 로그인/결제 권한/재접속 PPT 다운로드 15개 항목과 홈페이지 생성·공개·복원·문의 16개 항목도 통과했다. 인증된 홈페이지의 PC/모바일 브라우저 11개 항목도 통과했다. Google 로그인, 실제 PG 테스트, Cloudflare 실행 환경과 PPT 브라우저 다운로드 UI는 별도 검증이 필요하다.
사용자는 가상 데이터 AI/PPT 검증 비용을 총 5달러까지 승인했다. 로컬 검증 이후 외부 테스트 리소스 생성도 추가 승인했으며, 유료 플랜 변경·운영 배포·실제 결제는 제외했다. 실제 OpenAI 호출 3건을 완료했으며 PG 결제는 0건이다. 자세한 증거는 [실제 AI/PPT 검증 기록](./ai-ppt-live-validation-2026-09-13.md)에 정리했다.

## 외부 스테이징 준비

- `today-startup-staging` Worker를 새로 생성했다. 공개 URL/preview URL/도메인 연결 없이 503 준비 중 응답만 배포했다. 실제 앱 공개가 아니다.
- 운영 환경변수를 읽지 않는 격리 빌드 도구, 스테이징 설정 검사, 운영 DB와 유료 키 혼입 시 요청 차단을 추가했다.
- OpenNext 실빌드와 최종 Wrangler 번들 검사, 로컬 Worker 차단 5/5, 회귀 35/35, 타입 검사를 통과했다. 전체 앱의 원격 실행 검증은 아직 아니다.
- Supabase는 현재 Free 플랜 활성 프로젝트 2개를 사용 중이다. 운영 `newapp`과 용도 미확인 `testapp`은 변경하지 않았고 전용 테스트 DB 생성은 보류했다.
- 작업 순서, Google GIS 인증 검증, PG sandbox, PPT 재다운로드, 홈페이지와 개선 리포트 검증, 출시 통과 기준은 [스테이징 실행 계획](./staging-rollout-plan-2026-09-13.md)에 정리했다.
- 이번 단계의 추가 유료 AI/PG 호출, 운영 마이그레이션, 운영 배포, 커밋/푸시는 없다.

## 운영 관측 적용

새 마이그레이션 `0029_generation_observability.sql`은 **로컬 테스트 DB에만 적용**했다.
배포 시에는 DB 마이그레이션을 먼저 적용하고 관리자 API/화면과 호출 메타데이터 기록 코드를 함께 배포한다. 운영 적용은 별도 승인 후 진행한다.

홈페이지 `0030_homepage_lifecycle.sql`도 **로컬에만 적용**했다. 운영 적용 전에 기존 중복 연결/공개 주소를 점검해야 하며 새 버전 확인 API와 클라이언트를 함께 배포해야 한다. 점검 SQL과 배포 순서는 홈페이지 검증 문서에 기록했다.

- 최근 7일 내 저장된 계정 최대 1,000개를 대상으로 현재 작업 상태를 조회한다. 전체 작업 감사 이력이 아니다.
- `admin_generation_jobs` RPC는 service_role만 실행할 수 있고 원문 데이터 대신 필요한 메타데이터만 반환한다.
- UI는 20개씩 조회하며 상태 필터를 제공한다. 목록은 실시간 갱신 중 변경될 수 있다.
- AI 호출 목록은 최근 25건이다. 모델/시간/오류 칼럼이 없던 과거 기록은 0이 아니라 미기록으로 표시한다.
- 새 칼럼이 없는 배포에서는 기존 토큰/횟수 기록으로 제한적으로 되돌아간다. DB 장애를 성공이나 0건으로 표시하지 않는다.
- 자동 장애 알림의 수신처, 플랫폼 전체 일일 비용 차단, 관리자 수동 재시도 권한 및 감사 기록은 아직 남아 있다.

## 실제 AI/PPT 실행과 재개

키를 로컬 `.env.local`에 설정한 뒤 비용 없는 사전 점검과 실제 검증을 완료했다. 이후 설정 변경 시에도 먼저 사전 점검을 실행한다. 비밀키를 채팅이나 저장소에 남기지 않는다.

```sh
node --env-file=.env.local --import tsx scripts/deck-ai-smoke.ts
```

사전 점검 기본 동작은 유료 호출 0건이다. 사용자 설정 완료 확인 후 다음 명령을 사용한다.

```sh
node --env-file=.env.local --import tsx scripts/deck-ai-smoke.ts --run-paid-synthetic --approved-budget-usd=5
```

- 고정된 가상 사업/기간 기록만 사용한다. 운영 DB와 Anthropic 연결을 제거한다.
- 기존 기획 모델 `gpt-6-astra`를 유지한다. 다른 모델은 단가 검토 전 차단한다.
- `store:false`, Standard tier 강제, 텍스트 입력만 허용하고 도구/이미지/배경 요청은 차단한다.
- `artifacts/synthetic-ai-launch/budget.json`에 호출 전에 보수적인 최대 비용을 예약한다. 타임아웃이나 강제 종료도 예약액을 반환하지 않는다.
- 실행 간 누적 상한은 5달러이며 동시 실행은 잠금으로 막는다. 단가 기준은 [OpenAI 공식 가격표](https://developers.openai.com/api/docs/pricing)의 2026-09-13 확인 내용이다. 향후 재개 시 단가를 다시 확인한다.
- 예약액은 실제 청구액이 아니다. 입력 UTF-8 바이트와 여유분, 최대 출력 토큰, 긴 문맥/캐시 쓰기 요금을 보수적으로 적용하므로 5달러보다 일찍 멈출 수 있다.
- 오류 시 외부 제공업체 폴백이나 무제한 재시도를 하지 않는다. 예약 장부를 삭제해 예산을 초기화하지 않는다.
- 분석, PPT 초안/검토 결과, 이벤트, 실제 `.pptx`를 보관한다. 완료 결과가 있으면 다시 AI를 호출하지 않는다.
- 이 상한은 **이번 검증 스크립트**에만 적용된다. 운영 플랫폼 전체 비용 제한 기능과 혼동하지 않는다.

## 남은 순서와 통과 기준

1. **실제 AI/PPT 잔여 검증**: 가상 사업 1건의 생성/검토/파일 검사는 완료했다. 실제 PowerPoint 앱 호환성과 긴 입력/다른 업종/실패 후 복구의 추가 표본은 미검증이다. 추가 유료 호출은 기존 누적 장부를 유지하며 한도 안에서만 실행한다. 파일 생성만으로 출시 통과 처리하지 않는다.
2. **외부 스테이징 인증**: 별도 Supabase와 Google 테스트 설정을 준비한 뒤 비회원 대화 → Google 로그인 → 같은 사업/자료 복원을 확인한다. 이메일 확인, 재로그인, 계정 전환, 다중 탭, Cloudflare Workflow도 포함한다.
3. **테스트 결제/다운로드**: 로컬 결제 상태별 권한과 인증된 PPT 재다운로드는 통과했다. PG 테스트 키와 콜백 주소 확정 후 실제 테스트 승인/취소/실패/중복/환불, 브라우저 재접속 다운로드를 확인한다. 실제 결제는 실행하지 않는다.
4. **홈페이지 스테이징 반복**: 로컬 Auth/DB/HTTP 전체 흐름 16개와 인증된 브라우저 저장/공개/문의는 통과했다. 같은 시나리오를 실제 테스트 권한과 Cloudflare에서 반복하고 외부 사진, 이미지 업로드, 커스텀 도메인, 문의 알림 전달을 추가 확인한다.
5. **운영 준비**: 장애 알림 수신처와 예산 정책, 지원 담당자/연락 경로, 실패 재개 절차를 확정한다. 전문 서비스는 제공 범위/견적/담당자/기한이 확정된 분야만 공개한다.
6. **제한 출시**: 위 증거를 검토한 뒤 사용자 승인으로 운영 마이그레이션/배포를 수행하고 새 계정의 첫 여정을 다시 확인한다.

검증 전에는 `OPERATING_AI_ENABLED`, `NEXT_PUBLIC_PPT_GENERATION_VERIFIED`, 결제 개방을 임의로 활성화하지 않는다. 이미 계정 이전이 이루어진 운영 환경에서는 소유권 보호 코드를 과거 버전으로 되돌리지 않는다.
