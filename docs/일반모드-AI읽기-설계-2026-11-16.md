# 일반 모드 — "AI가 읽고, 코드가 계산한다" 설계 (2026-11-16)

아직 사이트 코드는 바꾸지 않았습니다. 이 문서를 보신 뒤에 바꿉니다.
시험 결과는 `일반모드-AI읽기-시험-2026-11-16.md`에 있습니다(작은 모델 59/60, 한 번 0.6원, 평균 1.8초).

## 한 줄 요약

사용자가 무슨 말을 적든 작은 AI가 읽어 **사업 정보 표**를 고치고, 계산과 검사는 코드가 합니다. 말투가 새로 나와도 코드를 고치지 않습니다.

## 1. 흐름

1. 사용자가 입력칸에 말을 적어 보낸다(선택 단추를 누른 경우는 지금처럼 바로 저장 — AI를 부르지 않는다).
2. 서버가 작은 AI(Haiku 5.5)를 한 번 부른다. 넘기는 것: 지금 묻는 칸, 지금까지의 표, 방금 적은 말.
3. AI가 돌려주는 것: 고칠 칸과 값과 근거 말 · 모른다고 한 칸 · 되물어야 할 칸.
4. 코드가 검사한다(아래 3번). 통과한 것만 표에 넣는다.
5. 표가 바뀌었으면 계산표를 다시 만든다. 되물어야 할 칸이 있으면 그 질문을, 없으면 다음 빈 칸을 묻는다.

## 2. 표를 어디에 저장하나

- **새 DB 표는 필요 없습니다.** 지금도 사업마다 "칸 · 값 · 누가 말했는지 · 근거 말"을 저장하고 있고(전문가 모드와 사업 방향 정리가 쓰는 것), 그 자리를 그대로 씁니다.
- 새로 생기는 칸은 하나: **주당 영업일**. 하루 처리량은 지금 "대표자 혼자 / 하루 80건"처럼 글로 저장하는데, 그대로 둡니다.
- 칸마다 출처를 둘로 나눕니다: **직접 말함**(근거 말 있음) / **업종 기준값으로 채움**. 지금과 같습니다.
- 질문과 다른 말은 지금처럼 메모로도 남깁니다(대화 기록용). 다만 내용은 표에 들어가므로, 오늘 만든 "메모를 참고 자료로 넘기기"는 보조 역할이 됩니다.

## 3. 코드가 하는 검사 (AI가 지어내는 것을 막는 곳)

- 근거로 댄 말이 사용자가 실제로 적은 글 안에 있는지. 없으면 그 칸은 버린다. (시험 180번의 답에서 위반 0건)
- 숫자가 말이 되는 범위인지(영업일 1~7, 주당 시간 168 이하, 금액 0 이상 등). 지금 있는 검사를 그대로 쓴다.
- 금액이 터무니없이 크거나 작으면 "이 금액이 맞나요?"를 한 번 묻는다. 지금 있는 확인을 그대로 쓴다.
- 직접 말한 칸을 AI가 근거 없이 바꾸려 하면 버린다.

## 4. 계산표가 표를 어떻게 읽나

- 지금: "하루 80건"에 **무조건 26일**을 곱해 한 달 판매량을 만든다. 영업일이 계산 코드에 박혀 있다.
- 바꾼 뒤: 표의 **주당 영업일** 칸을 읽어 곱한다(주말만이면 2일 × 4.3주). 칸이 비어 있으면 지금처럼 26일(주 6일)로 계산하고, 계산표에 "주 6일 영업 가정"이라고 적는다.
- 26을 쓰는 곳은 열 군데쯤입니다(한 달 환산, 하루 본전, 배송 가능량, 목표 판매량 등). 한 곳에서 영업일을 정하고 나머지가 그 값을 쓰도록 모읍니다.
- 앞으로 다른 가정(영업시간, 휴무 등)이 필요해지면 같은 방식으로 **표의 칸으로** 넣습니다. 계산 코드에 숫자를 박지 않습니다.

## 5. AI가 실패하면

- **3초 안에 답이 없거나 오류**면: 지금의 규칙으로 읽습니다(오늘 고친 것들 포함). 사용자는 차이를 모릅니다.
- **형식이 깨진 답**: 형식 강제 설정을 켜 두어 시험에서는 0건이었습니다. 그래도 나오면 위와 같이 규칙으로 넘어갑니다.
- **검사에서 다 버려진 답**: 적은 말을 메모로 남기고 같은 질문을 이어 갑니다(지금과 같음).
- 실패는 기록으로 남겨, 얼마나 자주 넘어가는지 볼 수 있게 합니다.

## 6. 지금 규칙 중 무엇을 지우나

**바로 지우지 않습니다.** 먼저 대비용으로 남기고, 2주쯤 실패 기록을 본 뒤 지웁니다.

| 지금 규칙 | 처리 |
|---|---|
| 한글 숫자 읽기("삼백", "이천만원") | 대비용으로 남김 → 나중에 지움 |
| "몰라 알아서 해줘" 읽기 | 대비용으로 남김 → 나중에 지움 |
| 업종을 적어 보내면 가까운 업종 고르기 | 대비용으로 남김 → 나중에 지움 |
| 질문과 다른 말 분류(메모/질문/되묻기) | 대비용으로 남김 → 나중에 지움 |
| 영업일 규칙(만들다 멈춘 것) | **반영하지 않고 버림** — 표의 칸으로 대체 |
| 업종 기준값으로 빈 칸 채우기 | **남김** — AI가 아니라 표를 채우는 기본값 역할 |
| 숫자 범위 검사 · 금액 확인 | **남김** — 3번의 검사 |
| 선택 단추로 답하기 | **남김** — AI를 부르지 않음 |

## 7. 비용과 속도

- 말 한 번에 0.6원, 평균 1.8초(가장 느린 것 3.8초). 대화 한 번(다섯 번쯤 적는다면) 약 3원.
- 선택 단추만 누르는 사용자는 0원입니다.
- 기다리는 동안은 이미 만들어 둔 "적은 글을 읽고 있어요" 한 줄이 보입니다.

## 8. 붙이는 순서

1. **계산표가 영업일 칸을 읽게** 한다(26을 한 곳으로 모으기). AI 없이도 의미가 있고, 검사로 확인된다.
2. **AI 읽기를 서버에 넣되 켜지 않는다.** 스위치로 끌 수 있게.
3. **그림자 실행**: 며칠 동안 규칙이 실제로 처리하고, AI는 뒤에서 같은 말을 읽어 결과만 기록한다. 둘이 다른 경우를 모아 본다. (사용자에게 영향 없음, 비용은 말 한 번에 0.6원)
4. 차이가 납득되면 **일반 모드에서 켠다.** 규칙은 대비용.
5. 2주 뒤 실패 기록을 보고 대비용 규칙을 지운다.

## 9. 아직 정하지 않은 것

- 전문가 모드에도 같은 읽기를 쓸지(지금은 다른 AI 호출이 읽고 있음).
- 한 번에 여러 칸이 바뀌었을 때 "이렇게 읽었어요"를 어떻게 보여 줄지(지금의 "300만원으로 적었어요" 한 줄을 넓히면 됨).
- 되물을 때의 문장을 AI가 만들지, 정해 둔 문장을 쓸지. 정해 둔 문장이 싸고 안전하다.
- 그림자 실행을 며칠 할지, 실제 사용자가 생기기 전이라면 시험 문제로 대신할지.
