## 발견하고 수정한 표시 문제

실제 내 자료 화면에는 생성 기능이 닫혀 있는데도 `발표자료 PPT`가 일반 제공 형식으로 표시됐다. 또한 실패한 PPT에서 `제안서 편집본 열기`를 누르면 저장 상태 설명 없이 `생성 기능 검증 중` 버튼만 표시됐다.

이번 코드 변경은 다음 범위다. **이 문서 작성 시점에는 로컬 변경이며 아직 커밋·배포하지 않았다.**

- PPT가 검증 전일 때 내보내기 형식에서 제외하고 현재 결제 제공 범위에 포함되지 않음을 표시한다.
- 제안서 링크를 편집과 제작 상태 확인을 함께 의미하는 이름으로 바꾼다.
- 실패한 제안서 화면에 초안·작업 기록 보존 여부, 재시도 중지 상태, 문의 번호를 보여준다.
- 제작 상태를 GET으로 다시 확인하고 기존 사업계획서로 돌아갈 수 있다. 상태 확인 버튼은 생성 POST를 보내지 않는다.
- 이미 완료된 새 형식의 제안서는 생성 기능이 닫혀 있어도 편집본으로 열 수 있다. 실패한 초안을 완료된 제안서로 바꾸거나 검토를 우회하지 않는다.

검증 결과: 회귀 49/49, TypeScript 통과. `scripts/local-deck-status-browser.mts`에서 390px·1440px 실제 제안서 페이지, GET 전용 새로고침, 실패 안내, 원문 링크, 가로 넘침 없음, 브라우저 오류 0개를 확인했다. 이 로컬 화면 검사의 API는 모의 응답이며 실제 AI·PG 성공으로 계산하지 않는다.

최종 화면 검사 결과와 스크린샷: `artifacts/local-deck-status/1789474762212/`. 검증 서버는 종료했다.

### 실제 sandbox 결제창 검사

`scripts/nicepay-sandbox-browser.mts`는 운영 환경 파일을 복사하지 않은 임시 Next 앱과 기존 격리 로컬 Supabase(`127.0.0.1:55431`)만 사용한다. 발급받은 키 파일이 Git 제외·`0600`인지 검사하고, `S2_` Server/Basic 테스트 키와 sandbox API 주소를 강제한다. 새 로컬 가상 계정과 가상 사업으로 실제 HTTP 로그인·사업 저장·결제 준비 API를 호출한다. 유료 AI 기능은 모두 끄며 운영 DB는 연결하지 않는다.

최종 검사 `7b835f25`에서 다음을 확인했다.

- 실제 앱의 결제 준비 API가 서버 가격 149,000원의 주문을 생성하고 로컬 DB에 저장했다. 이 금액은 테스트 주문 금액이며 청구액이 아니다.
- NICEPAY SDK가 `sandbox-pay.nicepay.co.kr`로 연결됐으며 결제창에 `테스트결제(실결제불가)`가 명시됐다.
- 테스트 상점의 카드 선택·결제 확인 화면을 거쳐 삼성카드 인증 화면(`vbv.samsungcard.co.kr`)이 열렸다. 앱카드 및 일반/SMS/로그인 인증 선택지가 표시됐다.
- 카드번호나 카드사 로그인·본인인증 정보는 입력하지 않았다. 따라서 인증 콜백, 서버 승인, 구매 권한, 재접속 후 권한 유지, 취소·환불은 **통과 처리하지 않았다**. 검사 스크립트도 `passed: false`, `providerApprovalVerified: false`로 기록했다.
- 앞선 실행의 카드사 화면 대기는 검사 브라우저의 외부 호스트 허용 목록 때문이었다. 삼성카드 인증 호스트를 확인한 뒤 화면을 읽기 전용으로 검사했으며, 이를 앱의 승인 장애로 단정하지 않는다.
- 임시 브라우저와 Next 서버는 종료했다. 운영 Worker·운영 키·운영 결제 설정은 변경하지 않았다.
