# 실제 도메인 연결 문제 후속 검증

## 현재 판정

실제 도메인에서 발견한 홈페이지 준비 조건 불일치를 저장 데이터로 재현했다. 기존 로컬 보완 코드의 연결을 확인했고, PPT 제공 중지 상태의 안내와 상태 조회 동작을 수정했다.

**로컬 검증 완료이며 실제 도메인 배포는 아직 하지 않았다.** 이번 결과는 실제 AI 생성, PG 결제, Google 신규 로그인 또는 원격 Workflow 완주 결과가 아니다. 공개 PPT 생성 설정도 변경하지 않았다.

## 홈페이지 연결

대상은 실제 브라우저에서 확인한 가상 사업 `[QA 0911] 가게 소개글 테스트` 한 건이다. 승인된 `newapp`에서 해당 사업의 상품·고객·가격과 제한된 PPT 상태만 읽기 전용으로 조회했다. 계정 식별값이나 전체 대화는 가져오지 않았다.

- 기존 설문 키 `main_offer`, `first_target`는 비어 있어 배포본의 차단 조건을 재현했다.
- 대화형 사업안에는 상품 `메뉴 소개글 3개를 5만원에 시범 제공하고 수정은 1회`, 고객 `마포구 작은 카페`, 가격 `5만원`이 저장되어 있었다.
- `resolvePlanLandingContent`를 사용하는 현재 로컬 준비 검사에서는 누락 0개로 통과했다.
- 같은 원본으로 홈페이지 초안을 생성했고 저장 스키마와 편집용 페이지 데이터 생성을 확인했다.
- 조회 전후 해당 사업의 체크섬이 같았다. DB 쓰기, 홈페이지 공개, AI·결제 호출은 모두 0회다.

이 검사는 생성 함수까지의 연결 검증이다. 수정본이 반영된 실제 도메인에서 편집 화면 진입 → 저장 → 새 탭 복원은 배포 후 재검증해야 한다. 이미 편집한 홈페이지가 있으면 계획서 초안으로 덮어쓰지 않아야 한다.

## PPT 상태와 동작

`deckExportState`가 서버 제공 상태, 저장 작업, 원본 변경 여부에 따라 버튼 동작을 선택한다.

| 상태 | 동작 |
| --- | --- |
| 상태 미확인 또는 조회 실패 | 상태 다시 확인, 생성 요청 없음 |
| 제공 중지와 실패 초안 | 초안 보관과 재시도 중지 안내, 제공 상태 조회 |
| 제공 재개 확인 | 상태 조회 후 재시도 버튼 표시, 자동 생성 없음 |
| 현재 원본과 일치하는 완성 파일 | 제공 중지 여부와 무관하게 기존 파일 다운로드 |
| 원본이 변경된 파일과 제공 중지 | 제공 상태 조회, 오래된 파일을 최신 파일처럼 안내하지 않음 |
| 생성·다운로드·조회 중 | 중복 버튼 입력 차단 |

실제 QA 작업의 상태는 `failed`, 코드 `review_response_invalid`, 초안 있음, 문의 번호 `727ee46b`였다. 이번에는 해당 작업을 재생성하거나 삭제하지 않았다. '다시 시도하면 검토부터 이어갑니다'라는 실행 불가능한 안내를 제공 중지 상태에서 제거했다.

## 검증 결과

- 외부 호출을 차단한 회귀 테스트 **49/49 통과**
- TypeScript 검사 통과
- 격리 Next 개발 서버와 Playwright의 모바일 390px / PC 1440px 검사 통과
- 제공 중지 상태 버튼은 조회 횟수만 증가하고 생성 요청은 0회
- 서버 제공 재개를 조회해도 생성하지 않음
- 연속 클릭은 모의 작업 1건만 접수, 문서 다시 열기에서 기존 진행 상태 복원
- 제공 중지 상태에서도 완성된 공개 샘플 PPT를 두 번 다운로드, 10장 ZIP 무결성 및 파일 바이트 동일 확인
- 브라우저 런타임 오류 0건, 두 화면의 가로 넘침 없음, 임시 검사 서버 종료

브라우저의 PPT API 응답은 모의 서버이며 다운로드 파일은 기존 공개 샘플이다. 이를 실제 QA 사업의 PPT 생성·재접속 다운로드 성공으로 계산하지 않는다. 임시 서버에는 `.env.local`이나 DB·AI·결제 비밀키를 전달하지 않았다.

## 배포 후 순서

1. 승인된 두 문제의 최소 수정만 분리해 배포한다. 현재 작업 폴더의 다른 미커밋 변경을 통째로 배포하지 않는다.
2. 같은 QA 사업에서 홈페이지 진입·저장·새 탭 복원을 확인한다. 공개는 별도 승인 없이 하지 않는다.
3. 실제 문서의 PPT 메뉴에서 보관 안내·상태 조회를 확인한다. 이 검사를 위해 전 사용자 PPT 생성 스위치를 켜지 않는다.
4. 제한된 실제 생성 검증 환경과 남은 API 예산을 확인한 후 해당 QA 작업만 재개해 다운로드를 검증한다.

배포 범위 승인을 요청한 상태이며 커밋·푸시·운영 배포는 하지 않았다.
