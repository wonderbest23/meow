# 개선 우선순위 진행 기록

기준일: 2026-09-12. 로컬 변경이며 운영 서버에는 배포하지 않았다.
모의 검증 성공을 실제 OpenAI·로그인·결제의 종단 간 검증 성공으로 해석하지 않는다.
후속 실행 순서와 릴리스 조건은 [출시 보완 실행 계획](./release-roadmap-2026-09-12.md)에 관리한다.

## 1. PPT 정상 제공

상태: 안정화 구현 및 무료·모의 검증 완료. 실제 API 생성 검증은 대기.

- 신규 자동 생성은 `NEXT_PUBLIC_PPT_GENERATION_VERIFIED=true`를 명시하기 전까지 차단한다.
- 메인·이용 안내·결제 화면에서 PPT 자동 생성을 제공 준비 중으로 표시한다. 공개 샘플과 이미 완성된 PPT 내려받기는 유지한다.
- 잔액/지출 한도, 요청 빈도 제한, 응답 시간 초과, 응답 길이 제한을 구분한다.
- PPT 생성·검토에서 공급자 자동 전환을 끈다. 잔액·시간·연결 오류는 같은 작업에서 자동 재시도하지 않는다.
- 8~10장 생성, 본문 발췌 예산 약 32,000자, 별도 검토 자료로 요청량을 제한한다. 최신 공통 사업 정보는 유지한다.
- 생성 120초, 검토 90초, 수정 120초. 수정은 1회 후 재검토하며 검토 실패를 통과 처리하지 않는다.
- 형식 오류의 재구성은 최대 1회다. 사용자가 요청하는 작업 재시도는 기존 15분당 3회 제한을 유지한다.
- 검토 후 실제 PPTX 바이트를 생성할 수 있어야 작업 완료로 저장한다. 파일 제작만 실패하면 검토된 결과를 보관해 다음 시도에서 AI 호출 없이 파일 제작을 이어간다.
- 초안 여부에 맞춰 저장 상태와 재개 위치를 안내한다. 재진입·탭 복귀·온라인 복구 시 서버 상태를 조회한다.
- 중복 클릭은 동기 잠금으로 막는다. 접수 응답 유실 및 서버 오류 시 자동 재생성하지 않고 상태를 확인한다.

확인한 범위:

- 외부 네트워크와 실제 키를 제거한 회귀 테스트 17개 묶음 통과.
- 생성·검토·초안 복구, 소유자 분리, 원본 변경 차단, 완료 작업 재전달의 멱등성.
- 저장 결과를 새로 읽고 실제 8장 PPTX의 ZIP/CRC·슬라이드 내용 검사. 재렌더 시 추가 AI 호출 없음.
- 브라우저 개발 전용 모의 서버에서 중복 클릭 1회 접수, 응답 유실 후 진행 상태 복구, 화면 재진입, 공개 샘플 2회 다운로드 중 생성 요청 증가 없음.
- 메인 준비 중 안내의 모바일 453px 및 데스크톱 1440px 표시 확인.

실제 제공 전 필수 조건:

1. 연결된 OpenAI 프로젝트의 잔액 및 지출 한도 확인과 유료 테스트 허용.
2. 테스트 소유자의 저장된 사업 1건으로 실제 생성·검토·PPTX 다운로드.
3. PPT 파일의 모든 슬라이드를 실제로 렌더링하여 내용·한글·줄바꿈·겹침 확인.
4. 브라우저 재접속 후 같은 파일 다운로드, 추가 생성 호출 없음 확인.
5. 배포 환경의 Workflow 연결·실패 복구 확인 후 릴리스 플래그 활성화 및 재배포.

## 2. 로그인·결제 연결

상태: 코드/모의 검증과 로컬 Supabase 인증/DB 통합 검증 완료. 브라우저 종단 간 및 외부 스테이징/PG 검증은 미완료.

- 결제 화면에서 로그인으로 이동할 때 사업 ID·문서 유형·상품 파라미터를 유지하도록 수정했다.
- 서명 검증 전 취소/실패 응답은 주문 상태를 변경하지 않는다.
- 늦은 실패 응답은 `created` 주문만 변경한다. 완료·취소·환불 주문과 유료 권한을 덮어쓰지 않는다.
- 모의 DB로 완료/환불 상태 보호, 소유자별 권한 분리, 취소/위조 콜백의 비변경을 검증했다.
- 2차 보완: `plan_states`와 이전 이력을 SQL 트랜잭션으로 이전하는 경로를 추가했다. 대화/문서/실패 초안 보존, 동일 계정 재요청, 다른 계정으로 재이전 차단, 이전 중 실패 복구를 독립 SQL 엔진에서 확인했다.
- 2차 보완: 로그인 전 저장 완료 확인, 계정별 브라우저 캐시, 소유자 표식을 포함한 저장, 오래된 응답/종료 저장/재시도 차단, 로그아웃 후 자료 정리를 검증했다.
- 후속 검증: 로컬 격리 Supabase Auth/PostgreSQL에서 17/17 시나리오를 통과했다. 실제 토큰 발급/콜백/복구, 계정별 이전, 동시 요청, DB 롤백을 확인했으며 유료 AI와 PG는 호출하지 않았다.
- 실제 refresh token을 길이 때문에 거절하던 결함을 수정했다. 프로젝트/주문/설정의 후속 이전 실패는 `0028_account_link_retry.sql`의 계정별 완료 기록으로 재로그인 시 재개한다. 쿠키 교체 이후 복구와 다른 계정 격리를 검증했다.
- 신규 이전 기능은 `PLAN_ACCOUNT_LINKING_ENABLED=true`가 필요하며 기본 비활성이다. 로컬 테스트 환경에만 `0027`/`0028` 마이그레이션과 플래그를 적용했다. 운영 DB와 배포는 변경하지 않았다. [로컬 통합 검증 상세](./local-account-integration-2026-09-12.md).
- 남은 검증: 비회원 대화부터 로그인·결제·재로그인까지 같은 사업 유지, 다른 계정 전환 시 격리, PG 테스트 승인·취소·실패·동시 콜백, 승인 후 DB 저장 실패 및 환불 대조.

## 3. 장애·비용 관리

상태: 로그와 재시도 제어의 기초 보완. 관리자 운영 화면은 미완료.

- 개별 비스트리밍 LLM 호출의 모델·성공 여부·오류 코드·소요 시간·입출력 토큰을 기록한다.
- 공급자 전환 시 원래 공급자의 실패도 집계한다. 토큰 수는 기존 `0023_llm_usage_tokens.sql` 컬럼을 활용한다.
- PPT 작업 로그에 문의 토큰, 이전 단계 소요 시간, 전체 경과 시간을 남긴다. 사용자 원문과 API 키는 로그에 추가하지 않는다.
- 남은 작업: 관리자 단계별 실패 목록·처리 시간·토큰 집계, 알림 전달 채널, 예산 경보·중복 알림 억제, 실제 청구 비용 대조.
- 토큰 수는 청구 금액과 다르다. 모델별 최신 가격 및 공급자의 청구 내역 없이 원화 비용을 단정하지 않는다.

## 4. 수익모델 연결

상태: 이번 변경에서 구현하지 않음.

기존 자동 홈페이지 초안 기능과 연관된 맞춤 홈페이지 제작부터 완성하는 방향으로 범위를 제한한다.
실제 담당자·제공 범위·견적 및 납기 정책을 확정한 뒤, 요청 접수 → 운영자 견적 → 고객 승인 → 담당자 배정 → 진행 상태 → 결과물 확인 순서를 구현한다.
담당자와 정책이 준비되지 않은 분야를 연결 가능한 서비스처럼 표시하지 않는다. 마케팅·세무·사무실 지원의 동시 오픈은 보류한다.

## 로컬 검증 도구

- `node --import tsx scripts/reliability-tests.mts`: 모의 회귀 테스트. 외부 fetch와 실제 비밀키를 차단한다.
- 후속 보완 후 위 회귀 테스트는 20/20 통과. SQL 이전/충돌/롤백/RPC 권한 테스트와 별도로 로컬 Supabase의 실제 인증 및 병렬 연결을 17개 통합 시나리오로 검증했다.
- `scripts/local-account-lab.mts`: 운영 환경변수 없이 별도 Supabase 및 앱 복사본을 실행한다. `scripts/local-account-integration.test.mts`는 이 격리 환경만 허용한다.
- `/dev/deck-export`: 개발 모드 전용 브라우저 상태 복구 검증 화면. 내려받기는 공개 샘플이며 실제 AI·PG를 호출하지 않는다.
- `npm run lint`, `npm run build`: 타입·빌드 검사. 운영 배포 명령과 별개다.
