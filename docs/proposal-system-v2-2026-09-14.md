문서 목적을 고르는 새 UI는 아직 없다. 기존 생성 경로에서는 계획서 유형으로 목적을 추정하고, 라이브러리는 명시적 목적·업종·단계 옵션을 받는다. 투자·정부지원 자료는 공식 심사 양식이나 완성된 전문 IR 템플릿이 아니다. 대상 공고·독자별 추가 목차는 다음 확장 대상이다.

- 실적 없음: 가짜 KPI 대신 준비 현황과 검증 계획
- 비용 없음: 0원 처리나 임의 그래프 대신 필요한 입력과 계산 조건
- 가격 없음: 원문에 있는 제안 가격만 표시하거나 과금 단위·협의 조건 제시
- 일정 없음: 임의 날짜 대신 착수 조건과 완료 기준
- 이미지 없음: 임의 사진을 만들지 않고 이미지 없는 판형
- 승인된 이미지가 있으면 이미지 ID만 모델에 전달하고 실제 바이트는 검토 요청에서 제외

자료가 있다는 것은 사실이 외부 검증됐다는 의미가 아니다. 사용자 제공·예상·제안 표시는 원문 검토를 통해 유지한다.

## 구현된 변경 연결 로직

1. 원문의 항목별 변경을 비교한다.
2. 해당 항목을 근거로 쓰는 모든 슬라이드의 안정적인 ID를 찾는다.
3. 새 근거가 추가되거나 사업 정보가 바뀌면 전체 재검토 대상으로 올린다.
4. 수동 문구가 있는 페이지는 유지 또는 새 내용 사용을 명시적으로 선택한다.
5. 검토를 마친 대체 슬라이드를 승인할 때 위치·크기 편집을 보존한다.
6. 다른 탭이나 이전 버전의 승인 요청을 거절한다.
7. 직전 변경을 되돌릴 때 버전 번호는 증가시켜 충돌을 방지한다.

가격 수정 사례에서는 사업 요약·제공 범위·거래 조건 3쪽을 영향 대상으로 찾는 것을 검사했다. 이는 **모의 대체 내용으로 처리 흐름을 확인한 것**이며 AI가 수정 문장을 실제로 재작성했다고 주장하지 않는다. 계산값 갱신, AI 부분 재작성, 계정별 문서 보관, 드래그 조작은 별도 통합이 필요하다.

제목·요약·이미지의 위치·크기 값과 수동 제목·요약·노트를 따로 보관할 수 있고, 제목과 배치 변경이 실제 PPTX에 반영되는 것을 확인했다. 표 내부 셀 드래그, 자유 도형 추가, 이미지 업로드·자르기 UI는 아직 없다. PowerPoint에서 편집한 파일을 다시 플랫폼으로 가져와 동기화하는 기능도 없다.
