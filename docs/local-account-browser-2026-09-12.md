# 로컬 브라우저 다중 탭 검증

기준일: 2026-09-12. 이전 HTTP/DB 통합 검증에서 남았던 실제 브라우저 확인을 이어서 수행했다.
스테이징이 없으므로 사용자가 승인한 로컬 격리 환경만 사용했다.

## 범위

- 앱 `http://127.0.0.1:8094`, Supabase API `http://127.0.0.1:55431`, PostgreSQL `55432`.
- Codex 브라우저에서 계정, 목록, 대화, 문서, 사업 관리 탭을 직접 클릭해 검증했다. 자동화된 HTTP 테스트와 구분한다.
- 이전 통합 실행 `mtxynvib`의 로컬 이메일 테스트 계정 A/B를 사용했다.
- 운영 `.env.local`, 유료 AI/PG/메시징 키는 테스트 앱에 전달하지 않았다. Google 로그인 및 실제 결제를 실행하지 않았다.
- `/dev/account-sync`에서 고정 대화와 편집된 문서를 준비했다. 이 페이지와 서버 액션은 development, 정확한 로컬 Supabase 주소, 계정 연결 플래그를 모두 확인한다.
- 검증 사업 ID: `plan_beed38a5-8620-4f80-bf3a-008f1e9d9ff6`. 실제 고객 정보가 아닌 테스트 데이터다.

## 발견한 결함과 수정

저장 충돌로 미저장 초안이 남은 문서 탭은 `beforeunload`의 페이지 이탈 방지가 계정 전환용 새로고침까지 막았다.
다른 탭에서 로그아웃이 완료돼도 기존 본문이 화면에 남았다. 브라우저 화면에서 직접 재현했다.

- 소유자 변경을 알리는 공통 이벤트와 세대 번호를 추가했다.
- 계정이 바뀌면 PlanShell이 이전 화면을 제거하고 계정 확인 상태를 표시한다.
- 문서 편집의 진행 중 요청을 취소하고 대기 중 초안을 무효화한다. 늦게 도착한 응답이 이전 초안을 다시 기록하지 못하도록 확인한다.
- 문서, 사업안 직접 수정, 전문가 편집의 페이지 이탈 방지는 같은 계정에서만 작동한다. 계정 변경 후에는 이전 편집기로 저장하지 않는다.
- 같은 계정의 문서 저장 충돌 안내와 최초 저장본 보호는 그대로 유지했다.

로그아웃 시 기기의 미전송 입력/초안을 지우는 기존 보안 정책은 유지한다. 저장하지 않은 초안까지 서버에 보존된다는 뜻은 아니다.

## 서버 결과 대조

브라우저 시나리오 이후 로컬 DB를 읽기 전용으로 조회했다.

- 해당 사업을 가진 소유자 행은 정확히 1개이며 A의 계정 소유자다. B에는 없다.
- 사업 이름은 최초 테스트 이름으로 유지됐다. 저장하지 않은 두 사업안 편집값은 반영되지 않았다.
- 문서는 첫 탭이 정상 저장한 본문이며 늦은 충돌 초안으로 덮이지 않았다.
- 문서의 `edited=true`, `locked=true`와 고정 코치 대화 2개를 확인했다.
- 비밀키와 인증 토큰은 결과에 출력하지 않았다.

## 회귀와 재현

`scripts/plan-cache-owner.test.ts`에 소유자 변경 이벤트/세대 번호 검증과 편집기 방어 조건을 추가했다.
저장소 루트에서 다음 명령으로 모의 회귀를 실행한다.

```sh
node --import tsx scripts/reliability-tests.mts
npm run lint
npm run build
```

모의 회귀는 이번 수정 후 **20/20 묶음 통과**했다. 외부 AI/PG 성공 로그가 아니라 고정 응답을 쓰는 회귀 검사다.
타입 검사와 프로덕션 빌드도 통과했다. 빌드는 103개 정적 페이지 생성을 완료했으며 기존 middleware/로컬 Workflow 바인딩 경고는 남아 있다.
브라우저 시나리오는 별도의 수동 CUA 실행 기록이며 위 명령만으로 재현되지 않는다.

프로덕션 빌드를 임시 로컬 서버에서 실행해 `/dev/account-sync`도 확인했다. 테스트 조작 버튼이 없고 not-found 페이로드와 `noindex`가 포함됐다.
스트리밍된 응답의 HTTP 상태는 200이므로 HTTP 404 검증으로 기록하지 않는다. 서버 액션 자체의 development/로컬 DB/플래그 검사도 별도로 유지한다.

로컬 환경 준비는 [HTTP/DB 검증 문서](./local-account-integration-2026-09-12.md)를 따른다.
브라우저에서 고정 사업을 준비하고 두 문서 탭을 같은 버전으로 연다. 첫 탭을 수정/저장한 후 두 번째 탭을 수정/저장하면 충돌 안내가 나온다. 별도 계정 탭에서 로그아웃하고 두 번째 문서의 본문과 편집 UI가 제거되는지 확인한다.
같은 방법으로 대화의 직접 수정과 사업 관리의 전문가 편집에 미저장 입력을 남기고 확인한다.

## 다음 단계

1. 별도 스테이징 배포와 Supabase 테스트 프로젝트를 먼저 준비한다. 현재 아직 없다.
2. 스테이징에서 Google 로그인, 취소/복귀, 이메일 확인, 실제 배포 런타임의 탭 동기화와 세션 만료를 검증한다.
3. 테스트 비용 상한과 AI 사용 권한 확인 후 실제 PPT 생성, 전체 슬라이드 렌더링, 다운로드/재접속 다운로드를 검증한다.

브라우저의 강제 세션 만료, 느린 네트워크에서 계정 전환과 실행 중 AI 응답이 겹치는 경우, 모바일 실제 기기/여러 브라우저 엔진은 이번 검증에 포함하지 않았다.
세션 만료/응답 유실/소유권 충돌의 HTTP 검증 결과를 실제 브라우저 검증으로 확대 해석하지 않는다.
이번 수정은 로컬 변경이며 커밋, 푸시, 운영 활성화는 수행하지 않았다.
검증 종료 후 테스트 계정을 로그아웃하고 격리 앱/DB를 중지했다. 테스트 데이터는 보존했으며 기존 `http://localhost:8083` 미리보기는 다시 실행했다.
