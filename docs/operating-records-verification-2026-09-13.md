# 기간별 실적과 개선 리포트 검증

기준일: 2026-09-13. 로컬 작업본 기준이며 운영 배포 완료 기록이 아니다.

## 이번 구현

- 실제 `/plan/workspace?planId=...&tab=operations`에 `실적과 개선 기록` 메뉴 추가. 기존 사업과 여기서 새로 시작한 사업 모두 같은 사업 ID 아래에서 사용한다.
- 시작일/종료일, 실제 문의/주문/매출/지출, 고객 반응, 유지할 점, 바꿀 점, 다음 개선 행동과 확인 기준 저장.
- 겹치지 않는 기간을 최대 120개 보관한다. 각 기간은 최대 366일이며 이후 원본을 수정할 수 있다. 알 수 없는 값은 `null`, 실제 미발생은 `0`으로 구분한다.
- 선택한 기간보다 앞서 끝난 가장 최근 기간과 비교한다. 이전 값이 없으면 비교하지 않으며 이전 값이 0이면 증감률을 계산하지 않는다. 기간 길이가 다르면 합계만으로 개선 여부를 판단할 수 없다는 경고를 표시한다.
- 개선 행동과 확인 기준을 작성한 기록은 리포트로 별도 보관한다. 이번/이전 기간 전체 입력을 복제하므로 이후 원본을 수정해도 기존 리포트는 그대로 남는다. 원본 또는 비교 기준이 바뀌면 오래된 리포트임을 표시한다.
- 리포트는 최대 240개 보관하며 동일 입력 버전의 중복 보관은 막는다. 수정된 기록은 새 리포트로 보관할 수 있다. 각 리포트는 화면 조회 및 인증된 Markdown(.md) 다운로드를 제공한다.
- 리포트는 **사용자 입력과 수치 비교, 사용자가 적은 개선 행동의 보관본**이다. 자동 AI 진단, 실제 실적 검증, PDF/PPT 개선 보고서를 완성했다는 뜻이 아니다.

## 저장과 보호

- 기존 소유자별 `plan_states`의 `answers.__business_operations`에 저장한다. 별도 테이블/운영 마이그레이션은 적용하지 않았다.
- 전용 API만 운영 이력을 갱신한다. 일반 브라우저 자동 저장은 이 키를 만들거나 바꾸지 못한다.
- 기간별 개정 번호 및 플랜 저장 시점 비교로 동시 편집을 방어한다. 다른 기간의 동시 저장은 재시도해 둘 다 보관하고, 같은 기간의 충돌은 409로 알린다.
- 오래된 대화/문서 생성 작업이 전체 플랜을 저장해도 최신 운영 이력을 유지한다.
- 저장 및 보관 요청은 재시도해도 중복되지 않는다. 저장 중 이탈/미저장 이동 확인, 실패 시 입력 보존, 20초 요청 제한을 적용했다.
- 조회/다운로드는 소유권 검사와 `private, no-store`를 적용한다. 다른 사용자의 동일 사업 ID나 리포트 ID는 404다.

- 실제 브라우저 재접속: 기록 2개/리포트 2개가 복원되었고, 원본 매출 900,000원으로 수정 후에도 이전 리포트는 150,000원을 유지했다. 이전 리포트를 다시 선택해 다운로드 이벤트까지 확인했다. 모바일 문서/본문 너비는 뷰포트와 동일한 390px로 페이지 가로 넘침이 없었다.
