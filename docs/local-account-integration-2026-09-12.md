# 로컬 격리 계정 연결 검증

기준일: 2026-09-12. 사용자가 별도 스테이징 없이 로컬 격리 검증을 요청한 범위다.
운영 DB, Google 설정, PG와 유료 AI를 변경하거나 호출하지 않았다.

## 환경과 결과

- 독립 Supabase 프로젝트: `oneul-account-lab-20260912`, 로컬 PostgreSQL 17 및 Supabase Auth.
- 테스트 앱: `http://127.0.0.1:8094`, DB API: `http://127.0.0.1:55431`.
- 원본 앱을 임시 폴더에 복사하고 로컬 인증/DB 환경변수만 전달했다. `.env.local`과 외부 AI/결제/메시징 키는 복사하지 않았다.
- 모든 마이그레이션을 로컬 DB에 적용했으며 계정 연결 플래그는 격리 앱에서만 활성화했다.
- 실제 HTTP 인증과 DB 통합 시나리오 **17/17 통과**, 실행 ID `mtxynvib`.
- 결과: `artifacts/local-account-integration/report-mtxynvib.json`. 최신 실행 결과는 같은 폴더의 `report.json`.
- 대화, 문서, PPT 작업은 고정 테스트 데이터다. 실제 AI 호출 0회, 실제 결제 0회다.
- 기존 모의 회귀 **20/20 묶음 통과**, `npm run lint`, `npm run build`, `git diff --check` 통과. 빌드는 102개 정적 페이지 생성을 완료했다.
- 기존 `middleware` 규약 및 로컬 Workflow 바인딩 경고는 남아 있다. 빌드 성공을 배포 환경의 Workflow 동작 확인으로 해석하지 않는다.
- 검증 후 격리 앱/DB는 중지하고 테스트 데이터는 보존했다. 기존 미리보기 `http://localhost:8083`은 다시 실행했다.

## 발견하고 수정한 결함

1. 인증 콜백과 비밀번호 재설정에서 refresh token을 20자 이상으로 제한해 실제 Supabase가 발급한 12자 토큰을 거절했다. 공통 입력 스키마로 크기만 제한하고 토큰의 유효성은 기존 Supabase `setSession` 검증에 맡겼다. 짧다는 이유로 신뢰하지 않으며 잘못된 토큰은 여전히 거절한다.
2. `plan_states` 이전 후 기존 프로젝트/주문/설정 이전이 실패하면 비회원 쿠키 교체 때문에 후속 복구 대상을 잃을 수 있었다. `0028_account_link_retry.sql`에 완료 시각을 추가하고 로그인한 계정의 미완료 이력만 재개한다. 후속 단계 전체 성공 뒤 완료 처리하며 주문 이전의 DB 오류도 확인한다. 원래 계정의 재로그인에서 복구되고 다른 계정은 해당 이력을 이어받지 못함을 실제 DB에서 확인했다.

`plan_states`와 이전 이력은 하나의 트랜잭션이다. 기존 프로젝트/주문/설정까지 전부 하나의 트랜잭션이 된 것은 아니며, 후속 실패는 계정별 이력으로 복구하는 방식이다.

## 재현 절차

Docker Desktop, Supabase CLI와 `psql`, 설치된 앱 의존성이 필요하다. 저장소 루트에서 실행한다.

```sh
node --import tsx scripts/local-account-lab.mts prepare
node --import tsx scripts/local-account-lab.mts migrate
node --import tsx scripts/local-account-lab.mts serve
```

별도 터미널에서 검증한다.

```sh
node --import tsx scripts/local-account-integration.test.mts
node --import tsx scripts/reliability-tests.mts
```

앱 프로세스를 종료한 후 해당 테스트 DB만 중지한다. 데이터는 유지된다.

```sh
node --import tsx scripts/local-account-lab.mts stop
```

검증 스크립트는 임시 폴더의 표식과 로컬 DB 주소를 확인하고, 테스트 HTTP 요청을 위 두 로컬 origin으로 제한한다. 로컬 비밀키를 출력하지 않는다. 외부 스테이징/운영 URL로 치환해 실행하는 스크립트가 아니다.

## 남은 확인과 배포 조건

- 브라우저 도구의 로컬 탭 열기가 시간 초과되어 이번 차수의 화면 클릭/다중 탭 종단 간 검증은 미완료다. HTTP 동시 요청 검증과 구분한다.
- Google 공급자 로그인, 이메일 확인이 필요한 외부 환경, Cloudflare 런타임/Workflow는 미검증이다.
- 실제 PPT 생성과 모든 슬라이드 렌더링, PG 테스트 승인/취소/환불은 미검증이다.
- 운영에는 배포하지 않았다. 계정 연결 플래그는 원본/운영에서 활성화하지 않았다.
- 스테이징에는 `0027_plan_account_linking.sql`과 `0028_account_link_retry.sql`을 함께 적용하고 모든 웹/API/Workflow 저장 실행기를 같은 버전으로 맞춘 뒤 플래그를 활성화해야 한다.
- 외부 환경 검증 및 사용자 승인 후 운영 배포한다. 이전이 실행된 환경에서 플래그만 끄거나 구버전으로 되돌려 소유권 보호를 제거하지 않는다.
