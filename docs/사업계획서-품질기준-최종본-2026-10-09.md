# 사업계획서 품질 기준과 개선 계획 (최종본, 2026-10-09)

오늘창업 사업계획서를 무엇으로 평가하고, 어떤 방법으로 고칠지 정한 문서다. 프롬프트·장 구성·코드 검사를 바꿀 때는 이 문서를 기준으로 삼는다.

## 0. 전제

- **목적:** 창업자 본인이 보고 바로 실행하는 계획서다. 정부 지원사업(예비창업패키지 등) 제출용이 아니다. 심사위원을 설득하는 항목(시장 규모 자료, "왜 당신인가", 심사용 분량)은 기준에서 뺀다.
- **기준 자료:** 실제 창업 실행용 영문 자료를 주 기준으로 쓰고, 한국 소상공인 실정에 맞게 현지화한다. 국내 자료는 현지화 근거로 쓴다.
- **자료는 기준으로만 쓴다:** 자료의 문장을 번역해 계획서나 프롬프트에 넣지 않는다(저작권). "무엇을 담아야 하는가"만 가져온다.
- **근거 표시**
  - ✅ 원문을 직접 확인함
  - 🟡 요약·설명 자료만 확인함
  - ⚪ 출처 없음, 제안

## 2. 지금 계획서와의 차이

- **지금 구성(일반 사업계획서 9장):** 한눈에 보기, 문제와 해결, 상품·서비스, 핵심 고객, 가격 전략, 유통 전략, 홍보 전략, 비용, 실행 요약
- **채울 자리가 없는 항목:** 3(일부), 5, 6, 7, 8, 9, 10
- **재구성 초안(⚪, 3단계 시험으로 결정)**
  1. 한눈에 보기 (마지막에 쓰고 맨 앞에 둠)
  2. 손님과 문제
  3. 팔 것과 가격
  4. 첫 손님 모으기 (유통과 홍보를 합침)
  5. 돈: 남는 구조, 시작 자금, 12개월 흐름, 내 생활비
  6. 먼저 확인할 것과 12주 할 일
  7. 매달 볼 숫자
- **효과:** 9장에서 7장으로 줄어 원가와 분량이 준다. 5·7장의 숫자는 코드가 계산하고 AI는 해석만 한다.

## 4. 진행 단계

| 단계 | 내용 | AI 비용(⚪ 추정) |
|---|---|---|
| 0 | 이 문서 확정(사장님) | 0원 |
| 1 | 시험 사업 20개, 채점 코드, AI 채점표. 전문가 5개 채점으로 AI 채점 맞추기 | 0원 + 전문가 비용 |
| 2 | 지금 상태 점수 재기(핵심 장 2~3개 × 20개) | 약 2~3만 원 |
| 3-1 | 입력 빈칸 막기(나이·지역 등 이어서 묻기, 수정 창 직접 입력) | 측정 약 2~3만 원 |
| 3-2 | 지시문 정리 + 예시 + 분량 + XML 구조(3장 7~11번) | 측정 약 2~3만 원 |
| 3-3 | 장 재구성과 돈 장(코드 계산: 4~7번) | 측정 약 2~3만 원 |
| 3-4 | 실행 장(8~10번: 가정, 12주, 매달 볼 숫자) | 측정 약 2~3만 원 |
| 3-5 | 원가: 항상 도는 검토 빼기, 강도 낮추기. 점수가 유지될 때만 적용 | 측정 약 2~3만 원 |
| 4 | 사장님 전·후 비교 → 배포 | — |
| 5 | 오픈 후 실제 기록(수정 요청, 환불) 보기 | — |

- **합계:** AI 비용 약 12~18만 원, 전문가 검토 수만 원.
- **비용을 줄이려면:** 2·3단계 첫 회는 시험 사업 10개로 줄일 수 있다. 원문은 양을 권하므로 최종 비교는 20개로 한다.
- **원칙:** 한 단계에서 한 가지만 바꾸고, 바꿀 때마다 점수를 비교한다.

## 5. 결정 기록 (2026-10-10)

빵집 시험 사업으로 한 가지씩 바꾸고, 바꿀 때마다 비교했다. 채점은 API 채점기(Sonnet 5.5)와, 버전을 모르는 이 세션 안의 검토자(블라인드, API 비용 없음)를 함께 썼다. 두 채점의 순위는 매번 같았다. 실제 AI 비용은 약 1만 3천 원이 들었다.

| 바꾼 것 | 결과 | 채택 |
|---|---|---|
| 지시문 v2(공식 원문 절반만 적용) | 기존보다 낮음(API 18 vs 22) | 버림 |
| 지시문 v3(공식 원문 전부: 이유, XML, 예시 4개, "이렇게 하라", 분량, 점검 지시 제거) | 기존보다 높음(26 vs 22) | 상담 계획서 기본 |
| 채점기: effort high + 자세한 채점표 + 항목별 근거 | 같은 글 두 번 채점 시 24개 중 23개 같음, 버전 차이를 구분함 | 채택 |
| 돈 장: 최대치 손익표 대신 세 경우(조심·본전·목표) 12개월 통장 누적 | 6번 처음 통과, "1월부터 흑자" 오해 제거 | 신규 사업 기본 |
| 실행 장 '12주 할 일과 매달 볼 숫자' | 8·9·10번 크게 오름(블라인드 53점, 1위) | '일반'·'운영' 계획서 기본(10장·11장) |
| 대표 생활비 질문 + 생활비 포함 계산 | 7번 5점. 생활비를 빼면 초기 지출 한도가 약 2,400만 원 느슨해지는 위험을 잡음 | 신규 상담 기본 질문(14개) |
| 판단 기준 한 곳(진행·축소·변경, 같은 기간끼리), 초기 지출별 버티는 기간 표, 신고 전 판매 금지 | 블라인드 3차 1위(53점) | 기본 |

- **되돌리는 스위치(서버 설정):** `PLAN_SECTION_PROMPT=v1`이면 예전 지시문, `PLAN_CASHFLOW_SCENARIOS=0`이면 예전 손익표. 실행 장과 생활비 질문은 장·질문 목록에 들어가 있어 코드로만 되돌린다.
- **남은 일:**
  - 축소안 숫자(줄인 고정비·처리량) 계산
  - 장 사이 숫자 반복 줄이기
  - 업종별 인허가 항목(예: 식품 영업의 위생교육·건강진단결과서·건축물 용도). 공식 원문을 확인한 뒤 넣는다.
  - 오픈 후 실제 계획서 기록으로 다시 보기
- **시험 도구:** `scripts/plan-eval/run.mts`(기본은 지금 방식, `--legacy`는 예전 방식), `scripts/plan-eval/regrade.mts`(AI 채점만 다시)

## 6. 공식 문서 다시 대조 (2026-10-11, v4 작업 중)

Prompting best practices, Prompting Claude Opus 5·5.5·Sonnet 5.5, Effort, Develop tests, Reduce hallucinations, Increase output consistency, Mitigate jailbreaks, Prompt caching을 다시 읽었다. 예전 페이지인 Chain prompts, Multishot, XML tags, Long context tips는 이제 best practices 한 페이지로 합쳐져 있다.

- **이미 맞음:** 구체적 지시·번호, 이유 붙이기, 예시 4개, XML, 역할, 분량 지시와 끝에서 다시 알리기, 점검 지시 없음, "모르면 (확인 필요)", 자료로만 쓰기, 코드로 숫자 확인
- **고침(v4):** 채점 지시문 끝에 Sonnet 5.5 원문 문장 "Think the problem through before you answer."를 넣음. JSON은 마지막 완전한 값을 읽고 한 번 다시 시도함
- **v5에서 측정해 정함**
  - effort: Opus 5.5는 medium에서 시작하라고 함. 지금은 high

7차 뒤에 고친 것('둘 다 가진 문제'에서):
- 비용 장의 "(실행 장의 첫 유료 판매 주차와 같음)"을 뺐다. 실행 장이 첫 판매를 앞당기면 사실과 달라졌다. 이제는 "가장 길게 ○주로 잡았다"고 쓰고, 앞당긴 주 수별로 줄어드는 돈을 미리 준다. 실행 장이 직접 곱하면 근거 없는 숫자로 잡혔다.
- 매달 돈 내는 사업의 메울 금액을 '최소 ○원, 느리면 약 ○원'으로 보여 준다. 판단선 기준 최소치만 주면 손님이 느리게 늘 때 첫 결정이 모자랐다.
- 생활비 0원을 "고정비에 들어 있다고 답했다"고 단정하지 않는다. 고정비에 이미 넣었거나 다른 수입으로 메우는 경우로 쓴다.
- 실행 장의 '○개월차' 판단은 첫 유료 판매 주차에서 4주씩 지난 주에 둔다. 첫 판매 2~3주 뒤에 한 달 기준으로 판정하던 문제다.
- 계산 자료의 숫자는 표기까지 그대로 쓴다. 하루 약 3.6건을 '약 4건'으로 바꾸지 않는다.
- 운영 중 돈 표는 12개월로 늘렸다. 1개월차는 지금 그대로 두고, 고친 효과는 2개월차부터 반영한다. 생활비선에 걸린 가게에는 '판매 10% 감소 → 한 달 ○원 부족'과 비상금으로 버티는 달 수를 세는 줄을 넣었다. 하루 환산은 소수 한 자리로 쓴다.

9차 뒤에 고친 것('둘 다 가진 문제'에서):
- '다시 정하는 선'이 계획대로 가는 중에도 걸리던 문제를 고쳤다(SNS 2개월차). 메운 돈을 더해도 계획 경로의 잔고가 한 달 지출보다 낮아지면, 절대 금액 대신 표의 같은 줄과 견준다.
- 생활비선이 처리 한도를 넘으면 가격별로 '고정비가 얼마 이하면 한도 안'을 계산해 준다(펫시터: 5,000원이면 34만 원, 6,000원이면 86만 원 이하).
- 목표가 처리 한도를 넘으면 한도의 80%를 임시 목표로 준다. '월 거래 600건'처럼 단위 앞에 낱말이 낀 목표도 읽는다.
- 조심스러운 경우로 재방문 목표에 닿을 수 없으면 밝힌다(네일: 6개월 144건 < 최소 200건).
- 운영 중 가게는 부가세가 들어 있을 때의 생활비선과 지금 실적의 부족분을 보인다(김밥집: 월 4,783건, 한 달 약 164만 원 부족).
- 운영 중 사업의 수요 확인은 설문 대신 지금 가격 그대로 실제 주문을 받아 보는 시범으로 한다.

10차는 처음으로 두 사업에서 졌다. 9차 뒤에 고친 것 중 둘이 역효과였다.
- 네일: '다시 정하는 선'을 표의 '조심스러운 경우' 줄과 견주게 했더니, 판매가 중간에서 천천히 돈이 새는 경우를 못 잡았다. 이 상대 기준은 매달 돈 내는 사업(계획 경로가 따로 있는 경우)에만 쓰게 되돌렸다.
- 펫시터: 한도의 80% 임시 목표(월 416건)를 '닿으면 계획대로'로 읽었다. 그 판매량에서도 매달 약 275만 원 적자다. 생활비선이 한도 밖이면 임시 목표에 닿아도 '계획대로'가 아니라고 붙였다.

10차 뒤에 함께 고친 것('둘 다 가진 문제'에서):
- 부가세가 들어 있으면 바뀌는 생활비선을 판단 기준에 함께 적는다(네일 93건 → 104건).
- '하루 약 18명과 이야기해야'는 참고값이지 계약 기준이 아니라고 밝힌다. 계약 판단은 날짜를 잡은 수와 비율로 한다.

### 11차: 산으로 가지 않게 — 업종 전체 점검 (2026-10-13, 실제 API 약 47,400원)

0원 맞대결은 늘 바로 앞 회차와만 견줘서, 둘 다 가진 퇴보는 보이지 않는다. 그래서 22개 사례의 질문지를 0원으로 다시 뽑아 비교했다.

### 16차: 단위와 중단 기준을 계산에서 바로잡기 (0원, 9개 업종)

15차 후보 가운데 세 가지를 계산 코드에서 고쳤다.

  - 한국어 과외: 목표 월 40번, 본전 월 5번 = 학생 약 2명. 전에는 40,000원을 한 달 값으로 계산해 본전이 약 4배 가혹했다.

결과:

- 시험 자료 한계: 캔들 시험 자료의 상담 요약(저장된 옛 AI 답)에 준비 기간을 빼지 않은 옛 숫자(696,000원)가 남아 있었다. 작성자가 계산 자료를 따라 바로잡았다.
- 둘 다 가진 문제(17차 후보, 업종 공통):
  - 매달 판단표의 '계획대로' 선과 월별 판매선이 서로 달라, 목표대로 가도 '줄여서'로 판정된다(펫시터·캔들).
  - '메울 돈'이 계획 경로의 바닥만 메워서, 메운 뒤에도 다시 정하는 선에 걸린다(레시피 앱·SNS).
  - '가동률 50%' 같은 목표를 읽지 못해 목표 경우 줄이 없다(연습실, 두 차수 연속).
  - 운영 중 사업의 한눈에 보기에 '초기 지출 한도' 칸이 '계산 자료 없음'처럼 시스템 말투로 남는다(김밥집).

### 17차와 실제 API 8건 (2026-10-13, 프로모션 크레딧 44,064원)

17차부터는 0원 시뮬레이션 반복을 멈추고, 실제 API 결과에서 보인 것만 고치기로 했다(대표 결정). 시뮬레이션은 점수가 4/5 근처에서 멈췄고, 승패가 쓸 때마다 달라지는 차이로 갈렸기 때문이다.

17차 코드 수정(시뮬레이션 검증 없이 실제 API로 확인):
- 목표로 늘어나는 동안은 그달 판매선을 '계획대로' 선으로 쓴다. 판매선과 판단 기준이 갈리던 문제다(펫시터·캔들·연습실).
- 메울 돈은 가장 낮은 달에도 한 달 나가는 돈이 남는 금액으로 센다(레시피 앱·SNS).
- '가동률 50%' 목표를 처리 한도 × 비율로 읽는다(연습실).
- 운영 중 사업의 한눈에 보기는 '초기 지출 한도' 대신 '이번 개선에 쓸 돈 상한'을 쓴다.

실제 API 8건(업종별 1건: 네일·연습실·한국어 과외·캔들·펫시터·레시피 앱·이사·SNS 대행):
- 비용: 1건 5,230~5,845원, 합계 44,064원. 프로모션 크레딧에서만 빠졌다(US$221.18 → US$189.70, 직접 산 잔액 US$7.62는 그대로). 이번 달 사용액은 US$95.56 / 한도 US$100이다.
- 8건 모두 빈 장 없이 끝났다. 업종 점검(블라인드)은 8건 모두 4/5이고, 법적 순서가 크게 틀린 곳은 없었다.
- 코드 채점에서 고친 것:
  - 숫자만 적은 주차 표('| 1 |')를 못 읽던 채점 오류를 고쳤다(한국어 과외).
  - 생활비를 안 적었거나 0원인 사업 4건에 대표가 생활비를 가져갈 선이 없었다. 월 100만·150만 원일 때의 선을 예시로 넣었다.
- 실제 결과에서 여러 업종에 반복된 것을 고쳤다.
  - '결제 수수료(카드·오픈마켓)'가 네일·연습실·이사에도 나왔다. '카드 수수료, 판매·예약 플랫폼 이용료'로 바꿨다.
  - 공간을 빌리는 사업은 준비 기간 월세를 한 달만 뺐는데, 실행표는 계약부터 첫 판매까지 약 7주였다. 두 달로 센다.
  - 목표가 한도를 넘으면 매달 목표는 한도의 80%인데 통장 표 경로는 100%까지 늘었다. 경로도 80%에서 멈추게 했다(캔들·펫시터).
  - 업종 가이드의 단계 이름만 넘겨 핵심 사실이 빠졌다. 이사의 '새 허가는 나오지 않아 기존 허가를 넘겨받는다'가 그 예다. 단계 설명까지 넘기고 22건 캡처로 잘림 0건을 확인했다.
- 남은 것(다음 실제 실행에서 확인):
  - 두 단계 전환(재방문 → 결제, 체험 → 등록)을 한 비율로 계산해 필요한 대화 수가 적게 나온다(레시피 앱·한국어 과외).
  - 실제 API 결과는 시뮬레이션보다 약 10% 길다(표 포함 약 4만 5천 자).

### 실제 API로 한 건 (2026-10-13, 프로모션 크레딧)

조직에 들어온 프로모션 크레딧(Max 플랜 제공분)으로 네일샵 한 건을 실제로 만들었다. 5,050원이 들었고, 직접 산 잔액은 줄지 않고 프로모션 크레딧에서만 빠졌다. 이 사용액도 월 지출 한도(100달러)에는 잡힌다.
- 12주 실행 장이 비어 나왔다. 생각을 깊게(high) 하다가 출력 한도 16,192토큰에 걸려 잘린 것이다. 실행 장만 한도를 14,000+생각 여유로 올렸다. 그래도 잘리면 생각을 줄여 한 번 더 쓰게 했다. 고친 뒤 다시 쓰니 15,076토큰으로 끝났다.
- 같은 사업의 세션 안 8차(0원)와 맞대결한 결과는 세션 안 8차의 승리였다. 실행 장이 빈 탓이 가장 크다. 실제 API 쪽은 시술 범위(디자인 샘플 안에서만, 이전 젤 제거)와 결제 수수료가 더 낫다는 평이었다.
- 둘 다 가진 문제: '앞당기면 준비 기간 지출이 줄어든다'는 문구가 영업 달에도 계속 모자란다는 점을 가린다. '재방문 100명' 같은 횟수 목표를 매달 진도로 나누지 않았다. 남는 돈이 아주 작을 때 세금을 넣으면 적자가 된다는 점을 표에 보이지 않았다.
