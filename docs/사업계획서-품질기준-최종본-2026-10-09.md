# 사업계획서 품질 기준과 개선 계획 (최종본, 2026-10-09)

오늘창업 사업계획서를 무엇으로 평가하고, 어떤 방법으로 고칠지 정한 문서다. 프롬프트·장 구성·코드 검사를 바꿀 때는 이 문서를 기준으로 삼는다.

## 0. 전제

- **목적:** 창업자 본인이 보고 바로 실행하는 계획서다. 정부 지원사업(예비창업패키지 등) 제출용이 아니다. 심사위원을 설득하는 항목(시장 규모 자료, "왜 당신인가", 심사용 분량)은 기준에서 뺀다.
- **기준 자료:** 실제 창업 실행용 영문 자료를 주 기준으로 쓰고, 한국 소상공인 실정에 맞게 현지화한다. 국내 자료는 현지화 근거로 쓴다.
- **자료는 기준으로만 쓴다:** 자료의 문장을 번역해 계획서나 프롬프트에 넣지 않는다(저작권). "무엇을 담아야 하는가"만 가져온다.
- **근거 표시**
  - ✅ 원문을 직접 확인함
  - 🟡 요약·설명 자료만 확인함
  - ⚪ 출처 없음, 제안

## 2. 지금 계획서와의 차이

- **지금 구성(일반 사업계획서 9장):** 한눈에 보기, 문제와 해결, 상품·서비스, 핵심 고객, 가격 전략, 유통 전략, 홍보 전략, 비용, 실행 요약
- **채울 자리가 없는 항목:** 3(일부), 5, 6, 7, 8, 9, 10
- **재구성 초안(⚪, 3단계 시험으로 결정)**
  1. 한눈에 보기 (마지막에 쓰고 맨 앞에 둠)
  2. 손님과 문제
  3. 팔 것과 가격
  4. 첫 손님 모으기 (유통과 홍보를 합침)
  5. 돈: 남는 구조, 시작 자금, 12개월 흐름, 내 생활비
  6. 먼저 확인할 것과 12주 할 일
  7. 매달 볼 숫자
- **효과:** 9장에서 7장으로 줄어 원가와 분량이 준다. 5·7장의 숫자는 코드가 계산하고 AI는 해석만 한다.

## 4. 진행 단계

| 단계 | 내용 | AI 비용(⚪ 추정) |
|---|---|---|
| 0 | 이 문서 확정(사장님) | 0원 |
| 1 | 시험 사업 20개, 채점 코드, AI 채점표. 전문가 5개 채점으로 AI 채점 맞추기 | 0원 + 전문가 비용 |
| 2 | 지금 상태 점수 재기(핵심 장 2~3개 × 20개) | 약 2~3만 원 |
| 3-1 | 입력 빈칸 막기(나이·지역 등 이어서 묻기, 수정 창 직접 입력) | 측정 약 2~3만 원 |
| 3-2 | 지시문 정리 + 예시 + 분량 + XML 구조(3장 7~11번) | 측정 약 2~3만 원 |
| 3-3 | 장 재구성과 돈 장(코드 계산: 4~7번) | 측정 약 2~3만 원 |
| 3-4 | 실행 장(8~10번: 가정, 12주, 매달 볼 숫자) | 측정 약 2~3만 원 |
| 3-5 | 원가: 항상 도는 검토 빼기, 강도 낮추기. 점수가 유지될 때만 적용 | 측정 약 2~3만 원 |
| 4 | 사장님 전·후 비교 → 배포 | — |
| 5 | 오픈 후 실제 기록(수정 요청, 환불) 보기 | — |

- **합계:** AI 비용 약 12~18만 원, 전문가 검토 수만 원.
- **비용을 줄이려면:** 2·3단계 첫 회는 시험 사업 10개로 줄일 수 있다. 원문은 양을 권하므로 최종 비교는 20개로 한다.
- **원칙:** 한 단계에서 한 가지만 바꾸고, 바꿀 때마다 점수를 비교한다.

## 5. 결정 기록 (2026-10-10)

빵집 시험 사업으로 한 가지씩 바꾸고, 바꿀 때마다 비교했다. 채점은 API 채점기(Sonnet 5.5)와, 버전을 모르는 이 세션 안의 검토자(블라인드, API 비용 없음)를 함께 썼다. 두 채점의 순위는 매번 같았다. 실제 AI 비용은 약 1만 3천 원이 들었다.

| 바꾼 것 | 결과 | 채택 |
|---|---|---|
| 지시문 v2(공식 원문 절반만 적용) | 기존보다 낮음(API 18 vs 22) | 버림 |
| 지시문 v3(공식 원문 전부: 이유, XML, 예시 4개, "이렇게 하라", 분량, 점검 지시 제거) | 기존보다 높음(26 vs 22) | 상담 계획서 기본 |
| 채점기: effort high + 자세한 채점표 + 항목별 근거 | 같은 글 두 번 채점 시 24개 중 23개 같음, 버전 차이를 구분함 | 채택 |
| 돈 장: 최대치 손익표 대신 세 경우(조심·본전·목표) 12개월 통장 누적 | 6번 처음 통과, "1월부터 흑자" 오해 제거 | 신규 사업 기본 |
| 실행 장 '12주 할 일과 매달 볼 숫자' | 8·9·10번 크게 오름(블라인드 53점, 1위) | '일반'·'운영' 계획서 기본(10장·11장) |
| 대표 생활비 질문 + 생활비 포함 계산 | 7번 5점. 생활비를 빼면 초기 지출 한도가 약 2,400만 원 느슨해지는 위험을 잡음 | 신규 상담 기본 질문(14개) |
| 판단 기준 한 곳(진행·축소·변경, 같은 기간끼리), 초기 지출별 버티는 기간 표, 신고 전 판매 금지 | 블라인드 3차 1위(53점) | 기본 |

- **되돌리는 스위치(서버 설정):** `PLAN_SECTION_PROMPT=v1`이면 예전 지시문, `PLAN_CASHFLOW_SCENARIOS=0`이면 예전 손익표. 실행 장과 생활비 질문은 장·질문 목록에 들어가 있어 코드로만 되돌린다.
- **남은 일:**
  - 축소안 숫자(줄인 고정비·처리량) 계산
  - 장 사이 숫자 반복 줄이기
  - 업종별 인허가 항목(예: 식품 영업의 위생교육·건강진단결과서·건축물 용도). 공식 원문을 확인한 뒤 넣는다.
  - 오픈 후 실제 계획서 기록으로 다시 보기
- **시험 도구:** `scripts/plan-eval/run.mts`(기본은 지금 방식, `--legacy`는 예전 방식), `scripts/plan-eval/regrade.mts`(AI 채점만 다시)

## 6. 공식 문서 다시 대조 (2026-10-11, v4 작업 중)

Prompting best practices, Prompting Claude Opus 5·5.5·Sonnet 5.5, Effort, Develop tests, Reduce hallucinations, Increase output consistency, Mitigate jailbreaks, Prompt caching을 다시 읽었다. 예전 페이지인 Chain prompts, Multishot, XML tags, Long context tips는 이제 best practices 한 페이지로 합쳐져 있다.

- **이미 맞음:** 구체적 지시·번호, 이유 붙이기, 예시 4개, XML, 역할, 분량 지시와 끝에서 다시 알리기, 점검 지시 없음, "모르면 (확인 필요)", 자료로만 쓰기, 코드로 숫자 확인
- **고침(v4):** 채점 지시문 끝에 Sonnet 5.5 원문 문장 "Think the problem through before you answer."를 넣음. JSON은 마지막 완전한 값을 읽고 한 번 다시 시도함
- **v5에서 측정해 정함**
  - effort: Opus 5.5는 medium에서 시작하라고 함. 지금은 high
  - 별도 검토·고치기 단계: Opus 5 원문은 "빼도 손실 없음", best practices는 "초안→검토→수정"을 흔한 방식으로 소개. 원문끼리 방향이 다르므로 측정으로 정함
  - 캐시: 실측 결과 첫 묶음 4장이 캐시를 4번 따로 쓰고, 검토 단계는 캐시 0
- **유지(이유):**
  - 대표 답변을 표시 태그로 감싸라는 권고(Opus 5.5): 대표 본인이 쓴 글이고 JSON으로 감싸 있음
  - 긴 자료를 지시·예시보다 위에 두라는 권고: 2만 토큰 이상일 때의 권고이고, 우리 입력은 약 1만~1만 5천 토큰

## 7. v4 시험 결과 (2026-10-11, API 대신 이 세션 안에서 작성·검토)

10장을 실제 API로 쓰면 약 4천 원이 들어, 설계·목차만 실제 API로 만들고(약 200원) 장 본문은 이 세션 안에서 운영과 같은 지시문·같은 순서(4장 → 4장 → 실행 장 → 실행 요약)로 썼다. 채점은 버전을 모르는 검토자가 했다.

| 비교 | 결과 | 주요 차이 |
|---|---|---|
| v3 : v4 | 41 : 50 | v4: 초기 지출 한도에 준비 기간 생활비 반영(7,228,800원), 중단선, 상품 구성 후보, 대안 가격 표, 영업시간·결제·예약, 실행 요약의 결정 |
| v4 : v4.1 | 45 : 47 | v4.1: 아래 다섯 가지 장 사이 어긋남이 모두 사라짐. v4 쪽 12주 표가 조금 더 촘촘함 |
| v4.1 : v4.2 | 48 : 50 | v4.2: 12주 표에 '견적의 월 비용을 고정비와 비교해 다시 계산'·'한도 안일 때만 계약'·'문 열기 전 실제 설비로 하루 양 만들기'. 신고 언급 32회 → 15회, 근거 없는 숫자 0개 |

v4에서 고친 것(v4.1):
- 버티는 기간 표의 '남는 준비 예산' 칸이 준비 기간 생활비를 빼지 않던 계산 오류
- 시범 판매 방법이 장마다 다름: 원인은 설계 단계의 '먼저 해볼 일'이 신고 전 결제 판매를 권한 것. 설계 지시와 장 지시 모두 '신고 전에는 돈을 받지 않고 의사만 모음'으로 맞춤
- 첫 할 일: 한눈에 보기 = 12주 표 1주차 = 실행 요약
- 남은 상품 처리는 유통 장이 정함(가격 장과 서로 미루던 것)
- 수요는 대표 손님이 실제로 사는 요일·시간대에 확인
- 숫자 검사가 표의 적자(-8,592,700원)와 본문의 '8,592,700원이 빠집니다'를 다른 숫자로 보던 오류, 가격 단계(500원씩)를 근거 숫자로 추가

v4.2에서 고친 것: 신고 주의는 신고 순서를 정하는 장 한 곳에서만 설명, '12주 장에 있습니다' 안내는 첫 장에서 한 번, 한눈에 보기·실행 요약의 첫 행동은 한두 줄, 돈 장은 한도가 빠듯할 때 줄일 방법까지, 12주 표의 계약·견적·실제 설비 확인

v4.2 검토에서 나온 두 가지도 고침(v4.3):
- 판단 기준은 계약 전에 쓴다. 매장이 있어야 신고할 수 있는 업종은 계약 전에 돈을 받고 팔 수 없으므로, 돈을 받지 않은 예약 의사 수로 판단하되 실제 구매보다 많게 나오기 쉽다고 밝힌다. 이미 신고된 공간(공유주방·팝업 매장 등)에서 먼저 팔아 보는 안도 검토한다. '규모를 줄여 시작'은 '줄여 계약'으로, 문을 연 뒤는 매달 볼 숫자와 중단선으로 판단한다
- 실행 요약의 판단 뒤 행동은 12주 장과 같게 쓰고, 그 시점에 할 수 없는 행동은 쓰지 않는다

남은 일:
- 업종별 인허가 항목(위생교육·건강진단 등)은 공식 원문을 확인한 뒤 넣는다
- v5(비용): 같은 계산 결과(financialScenario)가 상담 자료와 업종 질문 자료에 두 번 들어가 장마다 약 1,500자씩 겹친다. 검토·고치기 단계, effort, 캐시와 함께 잰다

## 8. 다섯 유형 계획서 시뮬레이션 (2026-10-12~13, 0원)

매장(네일)·플랫폼(펫시터 연결)·앱(레시피)·B2B(SNS 대행)·운영 중(김밥집) 계획서를 이 세션 안에서 운영과 같은 순서로 끝까지 썼다. 계획서마다 버전을 모르는 검토자 1명이 12항목(60점)으로 채점하고, 장끼리 어긋난 곳을 찾았다. 검토자 한 명의 점수는 같은 글에서도 ±2점쯤 흔들린다.

| 사업 | 고치기 전 | 1차 | 2차 |
|---|---|---|---|
| 네일(매장) | 41 | 39 | 39 |
| 펫시터(플랫폼) | 41 | 39 | 41 |
| 레시피(앱) | 36 | 40 | 36 |
| SNS 대행(B2B) | 39 | 41 | 42 |
| 김밥집(운영 중) | 38 | 39 | 40 |
| 평균 | 39.0 | 39.6 | 39.6 |

점수 평균은 거의 그대로였다. 대신 검토자가 지적한 돈 계산의 틀린 점은 다음 검토에서 다시 나오지 않았다.

고친 것(`cashflow-scenarios.ts`):
- 구독·월 계약 사업은 '그달 돈 내는 손님 수'로 계산하고, 0명에서 쌓이게 했다. 예전에는 매달 새로 파는 것처럼 계산해 'SNS 대행은 일주일에 10곳을 찾아가야'가 나왔다. 판단선과 매달 목표는 월별 한 줄로 합쳤다.
- 준비 기간에도 고정비가 나가게 했다. 공간 사업은 문 열기 한 달 전부터, 그 밖의 사업은 준비 기간 내내다. 돈 흐름 표는 문 여는 날 잔고에서 시작한다.
- 초기 지출이 0원이어도 중단선 아래에서 시작하면 중단선 대신 시작 전 결정을 묻게 했다. 결정할 때 메울 금액(6개월 기준)도 함께 보여 준다. 네 사업에서 '문 열자마자 중단 검토'가 나왔었다.
- 판매가에 부가세가 들어 있을 때 한 건에 남는 돈과 생활비선을 보여 준다.
- 처리 한도를 다 채워도 생활비가 모자라면 모자라는 돈을 알려 주고, 닿을 수 없는 판단 기준이라고 밝힌다. 예전에는 '본전에 못 미친다'고 잘못 썼다.
- 구독 사업이 판단선대로 늘어도 통장이 바닥나는 달을 알려 준다.
- 비율의 분모는 직접 이야기를 나눈 사람으로 정했다. 글을 본 사람 수(노출)는 분모로 쓰지 않는다. 이야기를 나눈 수가 10보다 적으면 비율로 판단하지 않는다.
- 운영 중 사업은 매출 목표를 '하루 몇 건 더'로 바꿔 보여 준다.

지시문:
- 사업자등록 주에 과세 유형을 고르는 기준을 쓴다.
- 정기결제 전에 결제사 심사·통신판매업 신고·청약철회 안내를 넣는다.
- 남의 집에 들어가는 사업은 보험·출입·개인정보·신원 확인을 미리 정한다.
- 업종 가이드에 없는 인허가는 질문 문장을 함께 쓴다.
- 바로 쓸 문구·기준·시점은 앞 장 것을 그대로 따른다.
- 판단 주차의 기준은 앞 주차의 끝난 기준과 이어지게 쓴다.
- 돈 경고는 재무 장에서만 쓴다.

남은 것:
- '짧고 읽기 쉬움'은 다섯 사업 모두 2~3점이다. 같은 숫자가 장마다 되풀이된다.
- 운영 중 사업 상담에는 '대표가 가져갈 돈'과 '지금 비상금' 질문이 없다. 운영 중 12개월 표는 같은 판매량이 이어지는 평평한 표다.
- 계산은 준비 기간을 12주로 고정한다. 12주 장이 첫 판매를 더 일찍 잡으면 두 장의 숫자가 다르다.
- 검토자가 매번 다른 업종별 실무 공백을 찾는다. 예: 배달앱 원산지 표시, 계정 접근 권한, 생성형 AI라는 무료 대안.
