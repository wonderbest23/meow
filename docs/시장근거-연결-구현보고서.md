### 1-1. `lightweight-pdf.ts` 수정 — 발견한 버그

기존 `inlineText()`는 marked 토큰을 평문으로 펼치면서 `link` 토큰의 `href`를 버렸다.
그래서 `[원문](https://kosis.kr/...)`이 PDF에서 **"원문"이라는 글자만** 남았다 —
종이로 출력하면 출처를 따라갈 방법이 없다. DOCX 렌더러(`document-renderer.ts:101`)는
이미 `텍스트 (href)` 형태로 남기고 있었으므로 **같은 표기로 맞췄다**.

```ts
/* 링크는 주소까지 남긴다 — 종이에서는 글자만 남으면 출처를 따라갈 수 없다(DOCX 와 같은 표기) */
if (token.type === "link") return `${inlineText(token.tokens, token.text)} (${token.href})`;
```

## 6. 데이터 매핑 (지시서 §5 그대로 구현)

| 대상 | 우선순위 |
|---|---|
| `title` | `business.name` → `plan.title` |
| `sector` | `business.industry` |
| `customer` | `market/segments.first_target` → `market/personas.situation` → `overview/summary.buyer_type` |
| `problem` | `overview/problem.problems` → `business.description` |
| `model` | `market/products.main_offer` → `business.description` |
| `revenue` | `financials/revenue.revenue_streams` |
| `region` | `business.region` → `"대한민국"` |
| `archetype` | 업종 매핑표 (아래) |

배열 값은 `", "`로 자연스럽게 합친다.

| 업종 | archetype |
|---|---|
| 카페·음식점 / 오프라인 매장 | `local_retail` |
| 온라인 쇼핑몰 | `ecommerce` |
| IT·앱·웹 | `digital_service` |
| 교육·강의 / 서비스·용역 / 콘텐츠·크리에이터 | `professional_service` |
| 제조·생산 | `manufacturing` |
| 기타 / 미선택 | `undecided` |

**검색 전 최소 입력 체크** (`researchReadiness`)

- **필수**: (사업 설명 또는 상품·서비스) + 업종 → 없으면 검색 호출 자체를 안 하고 422 + 안내
- **권장**: 고객 · 해결하려는 문제 · 지역 → 있으면 안내만 하고 검색은 허용
- 안내 문구 예: `시장조사의 정확도를 높이려면 먼저 고객과 지역을 입력해주세요. 지금 바로 검색할 수도 있습니다.`

## 8. 아직 남아 있는 한계

1. **실제 검색 호출은 운영에서만 확인 가능** — 로컬 `.env.local`에 OpenAI 키가 없어, 실제 KOSIS 검색 결과로 생성된 본문은 확인하지 못했다. 운영에서 플랜 하나로 "공식자료 찾기 → 본문 생성"을 한 번 돌려봐야 완전한 확인이 된다.
2. **로그인 필요** — 질문 화면이 게스트에게 `PlanGate`로 막혀 있어 패널은 로그인 사용자에게만 보인다(기존 정책 그대로).
3. **섹션 배분이 키워드 규칙** — "사업체"류 단어가 없는 경쟁 근거는 세그먼트로 분류될 수 있다. LLM 분류는 지시대로 넣지 않았다.
4. **조사 쿼터 없음** — rate limit(12회/10분)만 있고 과금·횟수 제한은 없다.
5. **`verified` 승격 경로 없음** — 웹검색 근거는 항상 `needs_review`. `verified`는 data.go.kr 상가정보 API 경로에서만 나온다(의도된 설계).
6. **충돌 검사는 프롬프트 지시로만** — `consistency.ts`에 "사용자 시장규모 vs 공식 근거" 규칙은 추가하지 않았다(기존 15종 미변경 지시).
7. **개요 화면 일괄 실행 없음** — UI 최소 변경 원칙에 따라 질문 화면 3곳에만 두었다.

## 9. 다음 단계에서 하면 좋은 것

1. **개요 화면(`/plan/overview`)에 근거 요약** — "공식자료 N건" 배지 + 한 번에 검색 버튼.
2. **`consistency.ts`에 근거 충돌 검사 1종 추가** — 사용자가 적은 시장규모와 공식 근거가 어긋날 때 규칙으로 잡기(현재는 프롬프트 지시로만 처리).
3. **조사 쿼터** — `regen-quota` 패턴으로 문서당 조사 횟수 포함/추가 구매.
4. **PSST 고도화 기준 자료 확보** — 첨부된 「2026년 예비창업패키지 사업계획서 양식」을 참고자료로만 분석했고 **양식·질문·목차는 변경하지 않았다**. 다음 단계 설계에 쓸 사실:
   - 구성: 일반현황 → 창업 아이템 개요(요약) → **PSST 4부**(문제 인식 / 실현 가능성 / 성장전략 / 팀 구성)
   - **목차 1페이지 제외, 본문 10페이지 이내**
   - 양식 변경·삭제 불가. 이미지·표 삽입은 가능
   - **사업비**: 1단계 20백만원 내외 / 2단계 20백만원 내외 집행 계획표
   - **추진일정**: `00.00 ~ 00.00` 형식 표
   - **팀 구성**: 대표자 보유 역량(경영능력·경력·학력·기술력·노하우·인적 네트워크), 팀원 역량, 협약기간 내 채용 예정 인력, 협력 파트너·기관
   - → **현재 질문 138개에 없는 것: 대표자·팀원 경력/학력, 사업비 집행계획, 추진일정.** 다음 단계 질문 설계의 직접 근거.
