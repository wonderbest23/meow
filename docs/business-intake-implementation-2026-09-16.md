# 사업 진단 중심 대화 전환

## 적용 범위

메인 대화에 규칙 기반 진단을 추가했다. 공개 기본값은 아직 기존 흐름이며, 새 흐름은 빌드 환경의 `NEXT_PUBLIC_BUSINESS_INTAKE_V2=1`로 연다. 운영 배포, 외부 테스트 서버 배포, 실제 유료 AI 호출은 이번 검증에서 하지 않았다.

- 아이디어 탐색 / 구상한 사업 / 운영 중인 사업의 세 진입 유형
- 핵심 질문 각각 11개, 이미 확인한 항목 건너뛰기, 미정·이전 답변 수정
- 11개 업종의 선택 상세 질문 각각 4개
- 질문 분기·직접 답변·기본 요약·재무 계산·저장에는 외부 AI 호출 없음
- 사용자 입력과 AI 사업안을 별도로 표시하며 생성은 명시적 요청에서만 실행

## 대화 화면 보완

규칙 기반 진단을 별도 설문처럼 보여주던 화면을 기존 채팅 흐름으로 되돌렸다. 기존 환영 메시지와 시작 선택지를 사용하고, 질문과 답변은 대화 안에 쌓인다. 단일 선택은 즉시 답변으로 전송하며 직접 입력과 복수 선택은 고정된 하단 입력창에서 전송한다. 기본 질문의 판단과 저장에 AI가 개입하지 않는 원칙은 유지한다.

하단 입력창은 시작 전부터 표시한다. 처음 적은 사업 설명은 대화 생성과 사업 내용 저장을 한 번의 CAS 요청으로 처리하며 시작 유형 버튼 선택을 강제하지 않는다. 이미 입력한 사업 설명은 다음 질문에서 반복하지 않는다. 명시적인 아이디어 없음/운영 중 답변은 해당 분기로 시작한다. 자유 메모와 AI 도움은 같은 입력창의 별도 모드이며, 직접 답변을 AI 도움으로 자동 전환하지 않는다. 이전 답변은 말풍선에서 수정할 수 있고 모바일은 대화/사업 요약을 전환한다.

2026-09-16 추가 검증: 전체 70/70 회귀 묶음 및 타입 검사 통과. 브라우저에서 320/390/768/1440px, 모바일 높이 692px의 입력창 고정과 가로 넘침, 세 진입 유형 완주, 말풍선 수정, 다중 탭 충돌, 응답 유실 후 재전송, 첫 메시지의 새로고침/중복 저장 방지를 확인했다. 보고서는 `artifacts/business-intake/1789528690904/report.json`이며 31회 질문 DOM 전환은 약 4~14ms였다. 유료 API 호출 및 운영 배포는 없었다.

후속 전송 오류 수정: 첫 입력 이후 `introMessage`가 남아 전송 버튼을 잠그던 조건과 901px 미만에서 Enter 전송을 막던 조건을 제거했다. Enter는 전송, Shift+Enter는 줄바꿈이며 한글 조합 중에는 전송하지 않는다. 소프트웨어/카페 등 명확히 일치하는 선택지 이름은 타이핑해도 기본 답변으로 처리한다. 기존 임시 입력과 새 입력이 같으면 한 번만 저장하고 서로 다르면 둘 다 보존한다. UI 단위 검사, 서비스 23개 사례, 타입 검사를 통과했고 실제 인앱 브라우저에서 기존 입력 전송과 새로고침, 390px에서 첫 입력/선택지 타이핑/직접 답변 전송을 확인했다. 이 후속 수정의 실제 브라우저 검증은 인앱 브라우저로 수행했으며 앞선 CLI 브라우저 보고서는 화면 복원 시점의 기록이다. 추가 유료 API 호출은 없었다.

환영 화면 정리(2026-09-16 후속): 사업이 만들어지기 전에는 상단 저장 상태 바(`입력 중 · 이 기기에 보관`, 진행도)를 표시하지 않는다. 첫 저장 이후부터 저장됨/저장 중/저장 실패/저장 충돌과 `기본 질문 N/11`을 표시한다. 시작 전 저장 실패는 기존 오류 알림이, 전송 중은 보내기 버튼 스피너가 알린다. 환영 제목 위의 장식 문구 `생각이 사업이 되는 순간`은 진단 화면에서만 끈다(`CoachWelcome tagline={false}`). 홈페이지 폰 데모와 기존 대화 화면은 그대로다.

선택형 전환 0단계(2026-09-16 후속): (1) 복수 선택 답변이 내부 값(`b2b_service, software`)으로 말풍선·요약·사업 후보 카드에 표시되던 결함을 고쳤다. `intakeValueLabel`이 배열 값도 선택지 라벨로 바꾸며(intake-core.ts), 후보 카드 근거 문구는 업종 내부 값 대신 라벨을 쓴다(intake-questions.ts). (2) 운영 중 경로의 실적 기간 질문은 타이핑 형식 지시 대신 프리셋 칩(최근 1/3/6/12개월, 올해)과 `직접 선택`(날짜 선택기 2개)으로 답한다. 선택값은 기존 서버 검증 형식 `YYYY-MM-DD / YYYY-MM-DD`로 전송되므로 intake-core.ts의 기간 검증은 그대로다. 프리셋 계산은 `periodPresetRange`(model.ts)이며 월 말일은 대상 월의 마지막 날로 맞춘다. 입력창 타이핑은 예외 경로로만 남긴다. 검증: 타입 검사, business-intake-ui/questions/core/service 단위 검사, 70/70 회귀 통과, 격리 미리보기에서 복수 선택 라벨 표시와 프리셋 저장 확인.

헤더·상태 바·탭 정리(2026-09-16 후속, 소유자 승인): 헤더 아래 "저장됨 · 기본 질문 N/11" 바와 모바일 "대화 / 사업 요약" 탭 줄을 없앴다. 진행도는 헤더 아래 3px 진행선과 헤더 부제("기본 질문 3/11", `BusinessAppChrome`의 `subtitle`)로 옮겼다. 저장 상태 요소는 하나만 두고 `role="status"`·`data-status`를 유지하되, 저장 중·저장 실패·저장 충돌·불러오는 중일 때만 화면에 보이고 저장됨·입력 중은 시각적으로만 숨긴다(`srOnly`). 모바일(≤900px)에서는 헤더의 "사업 관리" 옆에 요약 토글 버튼(`actions` 슬롯, 답변 수 배지)이 답변이나 확정 필드가 1개 이상일 때만 나타나고, 누르면 요약이 대화 자리를 대신하며 상단 "대화로 돌아가기"로 복귀한다. PC(≥901px)는 요약이 오른쪽에 그대로 있어 토글·시트 헤더가 표시되지 않는다. 새 대화 첫 화면은 헤더 한 줄과 첫 질문만 남는다. 브라우저 회귀의 탭 단언은 헤더 토글과 복귀 버튼으로 바꿨다.

### 질문 전환과 스크롤 후속 보완

사용자 답변을 즉시 말풍선으로 표시한 뒤 점 세 개의 `다음 질문 준비 중` 상태를 거쳐 다음 질문을 보여준다. 600ms는 대화 표현을 위한 최소 간격이며 저장 요청을 늦추거나 AI를 호출하지 않는다. 저장 실패·충돌은 대기를 바로 해제하고 입력을 보존한다. 계정·경로 변경과 화면 종료에서는 이전 전환 타이머를 취소하며 모션 감소 설정에서는 추가 대기와 진입 애니메이션을 생략한다.

자동 스크롤의 기준을 다음 질문에서 마지막 사용자 답변으로 바꿨다. 짧은 답변은 다음 질문과 함께 보이고, 긴 답변은 끝부분을 유지한다. 사용자가 이전 대화를 읽으려고 스크롤하면 강제로 따라가지 않는다. 화면 크기 변경에도 위치를 다시 계산한다. 현재 질문의 뒤로가기 버튼은 제거하고 `아직 미정`을 명확한 보조 버튼으로 표시한다. 이전 답변 목록과 미복구 입력은 사업 요약으로 옮겼으며 말풍선의 개별 수정은 유지한다.

최신 브라우저 보고서: `artifacts/business-intake/1789530883270/report.json`. API 키 없는 격리 서버에서 세 진입 유형 완주, 320/390/526/768/1440px 답변·질문 동시 노출, 저장 충돌, 응답 유실 후 재접속·중복 방지, 첫 입력 전송과 모션 감소를 통과했다. 31개 답변의 사용자 말풍선 DOM 반영은 약 9~22ms, 다음 질문은 약 607~629ms였다. 앞선 보고서의 300ms 기준은 즉시 사용자 피드백과 규칙 계산에 적용하며 다음 질문의 연출 간격과 구분한다. 실제 인앱 브라우저에서도 선택 답변과 직접 입력 모두 점 세 개 표시와 말풍선 유지가 확인됐다. 유료 API 호출 및 운영 배포는 하지 않았다.

이 보완 이후 TypeScript 검사와 전체 신뢰성 테스트 70/70 묶음을 다시 통과했다. 사용자가 열어 둔 기존 사업의 답변은 변경하지 않고 별도 가상 사업으로 브라우저 입력을 검증했다.

### 사업 설명 기반 업종 추천

업종 질문에서 확인된 사업 소개·제공 상품의 문구를 사용해 추천 업종을 먼저 보여준다. `50만원으로 SNS컨설팅`은 기업 서비스로 추천하며, `이 업종으로 계속`을 눌러야 기존 answer API로 확정한다. `직접 선택하기`에서는 기존 11개 업종을 펼쳐 선택한다. 기존 업종 수정과 복구된 선택은 전체 목록을 사용하고 추천으로 덮어쓰지 않는다.

기존 제안서 업종 분류 규칙을 재사용하고 제공 형태와 고객 업종이 다른 경우를 일부 보완했다. 확정되지 않은 AI 제안·자유 메모는 추천 근거에서 제외한다. 단서가 없거나 부정 표현·복합 사업·상충하는 입력이면 수동 선택으로 남긴다. 규칙 기반 추천이므로 의미를 완벽하게 판별한다고 보장하지 않으며 확인 전 공통 사업정보와 결과물은 변경하지 않는다. 추가 AI 호출은 없다.

업종별 예시·미분류·고객 업종 구별·부정·복합 사업 등 18개 분류 사례와 확정 전 무변경·수동 선택 보존 검사를 UI 단위 테스트에 추가했다. TypeScript 검사 및 브라우저 회귀 검사가 통과했다. 최신 보고서 `artifacts/business-intake/1789531580929/report.json`에 320/390/526/768/1440px 화면, 추천 확인, 직접 선택, 재접속, 기존 업종 수정, 중복 클릭과 모호한 입력 검증을 기록했다. 유료 API 호출 0회이며 운영에는 배포하지 않았다.

## 저장과 AI 경계

공통 사업정보는 기존 coach 필드와 일반 answers에 둔다. `__business_intake`는 질문팩 버전, 원문, 질문 상태, 후보, 작업 상태, 요청 영수증을 보관한다. 업종을 바꾸면 이전 상세 답변은 질문 기록에 남기고 현재 문서 근거에서는 제외한다.

자유 메모는 원문부터 저장한다. 명확한 항목 라벨은 규칙으로 후보를 만들고, 복합 문장은 별도 추출 작업에 전달한다. 후보는 원문 근거가 일치해야 하며 사용자 승인 전 공통 정보에 반영하지 않는다. 값 비교와 항목별 입력 이력 비교를 함께 사용해 변경 후 원래 값으로 돌아온 경우도 재확인한다.

추출은 사업당 동시 1작업, 외부 호출 1회, 20초, 최대 1,200 출력 토큰이다. 자동 재시도나 제공자 폴백은 없다. 새로 대기한 메모만 다음 작업으로 묶으며 실패한 메모의 재시도는 명시적으로 요청한다. 로컬 브라우저를 닫으면 후속 대기 메모는 저장 상태로 남고 재접속 때 이어진다. 실행 상태 확인이 120초를 넘기면 미완료로 복구하며 원문은 보존한다.

저장 요청 제한과 AI 요청 제한을 분리했다. 실제 AI 실행 전 서버 공통 카운터를 확인하며 조회 실패 시 외부 호출하지 않는다. 기본 진단은 AI 한도가 소진돼도 계속된다.

대화/질문 상태, 진단 작업 상태, 문서 근거 버전을 분리했다. 동일 답변을 다시 저장하거나 메모·로딩 상태가 바뀌었다는 이유로 문서가 오래된 것으로 표시되지 않는다. 기존 문서·PPT·홈페이지의 승인형 갱신 경로를 유지한다.

문서 생성은 원자적 예약과 요청 영수증으로 중복 Workflow를 막는다. 완료된 같은 요청은 기존 실행을 반환한다. 비동기 해석 상태는 독립 증가 버전으로 보호해 늦게 끝난 문서 저장이 후보나 메모 상태를 되돌리지 못한다.

- 브라우저: 세 진입 유형 완주, 새로고침, 두 탭 충돌, 서버 저장 직후 응답 유실, API 키 없이 메모 저장 후 진단 계속

브라우저 측정은 클릭 후 질문 DOM 전환 시간이며 네트워크 왕복이나 실제 디스플레이 페인트 시간은 아니다. 최종 측정 30개 답변은 약 3~21ms였고 저장 응답을 450ms 늦춘 경우도 300ms 목표 이내였다. 저장 전에는 저장 완료로 표시하지 않는다. 외부 글꼴만 로컬 대체했으며 진단 API는 실제 로컬 서버에 요청했다. 최종 브라우저 보고서는 `artifacts/business-intake/1789526253089/report.json`이다.

테스트 결과는 `artifacts/business-intake/`에 기록한다. 로컬 미리보기는 API 키와 결제 설정을 전달하지 않는 `demo-memory` 환경이므로 서버 재시작 후 영구 보관을 보장하는 환경은 아니다. 영구 계정 이전 검사는 별도 로컬 PostgreSQL에서 수행했다.

## 공개 전 게이트

1. 변경 코드와 Workflow를 테스트 서버에 함께 배포하고 테스트 DB에 `0036_intake_account_claim.sql` 적용
2. 테스트 빌드에서만 `NEXT_PUBLIC_BUSINESS_INTAKE_V2=1` 설정
3. 실제 로그인 자료 이전, 원격 Workflow, 중단/재접속, 기존 결과물 연결 확인
4. 기존 비용 장부의 잔액과 실행별 상한을 재확인한 후 실제 AI 추출·도움·명시적 생성 검증
5. 운영 노출 후 `[business-intake]` 완료율과 `[business-intake-job]` 대기/실행 시간·오류를 기존 `[llm]` 실제 호출 로그와 구분해 관찰

이번 변경으로 운영 서버가 이미 전환됐거나 실제 AI 품질 검증까지 끝났다고 판정하지 않는다. 롤백 시 진행 중 자료를 삭제하지 않고 플래그만 되돌린다. 계정 이전 이후에는 기존 소유권 보호 기능을 끄지 않는다.
