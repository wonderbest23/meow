# B2B 제안서 편집기 1차 검증

## 범위와 결론

B2B 가상 사업 1개로 생성 파이프라인 → 편집본 생성 → 화면 편집 → 서버 저장 → 새 브라우저 로그인 → PPT 다운로드를 로컬에서 연결했다.

**AI 생성·검토 응답과 결제 승인은 모의 데이터다.** 로그인, Supabase 저장, 버전 비교, 브라우저 조작, PPT 바이너리 생성과 다운로드는 실제 앱 경로를 사용했다. 이 결과는 운영 AI 품질·Cloudflare Workflow·Google 로그인·실제 PG 결제 검증 완료를 뜻하지 않는다.

- 운영 Supabase 및 Cloudflare 배포 변경 없음
- 유료 AI 호출 0회, 기존 5달러 예산 장부 변경 없음
- 실제 결제 0회
- `NEXT_PUBLIC_PPT_GENERATION_VERIFIED`는 계속 false
- 커밋 및 푸시하지 않음

## 구현

- 편집 화면: `/plan/proposal?planId=...`
- 기존 사업계획서의 다운로드 메뉴에서 제안서 편집본으로 이동
- B2B 고객 제안서 유형을 생성 작업에 전달하고 fingerprint·재시작 검증에도 유지
- 완료된 v2 생성 결과를 별도 편집본으로 초기화, 생성 원본 보존
- 제목·설명·본문 항목·표 셀·발표자 노트 수정
- 제목·설명 및 이미 포함된 이미지의 드래그 이동, 크기 조정, 숫자 입력, 방향키 이동
- 1.2초 대기 후 자동 저장, 수동 저장, 미저장 이탈 경고
- 화면 편집 되돌리기, 슬라이드 초기화, 최근 20개 저장 버전 복원
- 편집 화면과 PPT 내보내기에 동일한 장면 데이터 사용
- PPT의 텍스트·표·도형을 편집 가능한 네이티브 객체로 생성
- 일반 PPT 다운로드 경로도 같은 생성 결과에 연결된 편집본을 반영

## 데이터 보호

`plan_states`의 해당 사업 `answers.__proposal_editor`에 원문 스냅샷, 생성 결과, 편집 값, 버전, 최근 저장 기록을 보관한다. 기존 계정 연결 및 Supabase CAS 저장 경계를 재사용하며 새 DB 테이블은 만들지 않았다.

- 소유 사업 및 해당 사업의 유료 이용 권한을 매 요청에서 확인
- 클라이언트는 새 DeckPlan이나 이미지 URL을 직접 업로드할 수 없음
- 수정 가능한 필드, 문자열 길이, 표 구조와 슬라이드 좌표를 엄격하게 검증
- `expectedRevision`이 다르면 409로 차단하고 미저장 입력 유지
- 요청 UUID와 서명으로 응답 유실 후 중복 저장 방지
- 이전 저장 요청을 재전송해도 더 최신인 다른 탭의 버전을 묵시적으로 승인하지 않음
- 일반 사업 상태 자동 저장 및 늦게 완료된 생성 작업이 편집본을 덮어쓰지 못함
- 원문 변경 시 경고와 영향받는 슬라이드 수 표시, 기존 편집본은 보존
- 원문 변경 후 편집기에서 받는 파일은 저장 당시 스냅샷이며 자동 갱신된 문서가 아님

`scripts/local-proposal-editor.test.mts`: 별도 로컬 Supabase `127.0.0.1:55431` 및 개발서버 `127.0.0.1:8094`에서 검증.

1. 실제 생성 작업 함수에 모의 AI 응답을 넣어 12장 구성·검토·렌더·DB 저장
2. 비회원 및 미결제 계정 차단
3. 소유 계정의 모의 결제 권한 반영 후 편집본 생성
4. 제목 수정, 숫자 좌표 변경, 포인터 드래그 후 자동 저장
5. 표 셀 수정 후 저장
6. 새로고침 후 제목과 좌표 복원
7. 두 탭의 오래된 수정은 서버 내용을 덮어쓰지 않고 충돌 표시
8. 서버 저장 성공 후 응답만 유실시킨 상황에서 중복 방지 및 후속 입력 보존
9. 과거 버전 복원 시 새 버전 생성
10. 390px 모바일 편집과 저장
11. 320px·768px·1440px 화면에서 가로 넘침과 비어 있지 않은 미리보기 픽셀 확인
12. 로그아웃 후 새 브라우저 컨텍스트에서 이메일 로그인, 동일 편집본 복원, 실제 PPT 다운로드
13. PPT XML에서 수정한 제목·표 셀·좌표 및 12장 확인, 일반 다운로드 경로도 같은 편집 반영
14. 다른 계정의 읽기·쓰기·다운로드 및 일반 상태 API를 통한 편집본 위조 차단

- 전체 신뢰성 회귀 테스트: 40/40 통과
- 기존 업종·목적별 PPT 렌더 55개 조합 회귀 통과
- TypeScript 검사 및 `git diff --check` 통과
- 개발서버 종료·재시작 후 새 로그인으로 v11 편집본과 수정한 표지 복원 확인
- 실제 Microsoft PowerPoint 앱에서 편집하거나 되저장하는 검증은 하지 않음
- 로컬 이메일 로그인 검증이며 Google 로그인 검증은 아님
