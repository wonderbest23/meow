# 기간별 AI 개선안 연결과 격리 검증

기준일: 2026-09-13. 로컬 작업본의 구현 및 모의 검증 기록이다. 운영 배포나 실제 AI 분석 품질 통과를 의미하지 않는다.

## 이번에 연결한 흐름

1. `내 사업 > 실적과 개선 기록`에서 현재 기간과 직전 기간을 읽는다.
2. 사업명, 기간, 입력 실적, 계산된 증감을 미리 보여준다. 고객 반응과 작성 메모는 기본 제외이며 사용자가 포함 여부를 정한다.
3. 실제 전송 대상과 모델을 표시하고 별도 체크로 동의받는다. 자료, 기간 버전, 전송 대상이 달라지면 기존 동의로 실행하지 않는다.
4. AI 가설, 연결한 입력, 불확실한 점, 개선 행동을 구분해서 표시한다. 원인이나 개선 효과를 검증했다고 표현하지 않는다.
5. 사용자가 행동을 선택하고 직접 수정한 뒤 보관한다. 분석 당시 입력, 원래 AI 제안, 최종 선택 행동을 각각 보존한다.
6. 리포트 보관함에서 재열기와 Markdown 다운로드가 가능하다. 이후 기간 기록을 수정해도 과거 리포트는 바뀌지 않는다.

기존 사용자 작성 리포트도 그대로 사용할 수 있다. 이번 단계에서 자동 정기 발송, POS 연동, 리포트 PDF/PPT 변환, 다음 기간의 행동 달성 자동 평가를 추가한 것은 아니다.

## 안전 경계

- `OPERATING_AI_ENABLED=true`를 명시하지 않으면 실제 분석은 비활성이다. 운영 환경 변수나 배포 설정은 변경하지 않았다.
- 모의 응답은 development + demo-memory + BUSINESS_JOURNEY_LAB + Supabase URL 없음 조건에서만 사용한다. 화면과 내려받은 리포트에 모의 분석임을 표시한다.
- 실제 제공자 분석은 로그인한 사용자만 호출할 수 있다. 사업 소유권을 서버에서 다시 확인한다.
- 동일 요청 ID 재실행은 기존 결과를 반환한다. 사업별 동시 분석 1개, 최근 24시간 최대 3개 요청, 보관 60개로 제한한다. 실패도 횟수에 포함한다.
- AI 호출은 최대 45초, 출력 최대 4,000토큰이다. 자동 재시도나 동의하지 않은 다른 제공자로의 fallback은 하지 않는다. 실행 상태 확인만 반복한다.
- 저장 충돌 시 최신 기록을 다시 읽고 제한된 횟수만 저장을 재시도한다. AI 호출 자체를 이 재시도 안에서 반복하지 않는다.
- 분석 도중 원본/이전 기간이 바뀌면 결과를 `source_changed`로 남기고 오래된 자료로 새 리포트를 만들지 않는다.
- 90초 지난 실행 기록은 화면에서 미완료로 표시한다. 과거 입력은 보존하며 새로운 명시적 동의를 받은 요청만 허용한다.
- 시작/종료 시각, 결과 상태, 실패 코드, 응답에서 확인된 토큰 사용량과 모델을 분석 기록에 남긴다. 통합 운영 대시보드와 정확한 금액 산정은 별도 작업이다.
- Responses의 `store:false` 및 구조화된 출력은 기존 LLM 어댑터를 재사용한다. 구조화 형식 통과가 사실성이나 인과관계 검증을 보장하지 않으며 별도 사업 품질 평가가 필요하다. 구현 참고: [OpenAI Structured Outputs 공식 문서](https://developers.openai.com/api/docs/guides/structured-outputs).

## 검증 결과

- `scripts/reliability-tests.mts`: 29/29 묶음 통과. 인증정보 제거, 메모리 저장소, 외부 fetch 차단 환경이다.
- 신규 `operating-analysis.test.ts`: 동의 누락/변경, 미입력과 0 구분, 선택하지 않은 메모 제외, 없는 근거 ID/잘못된 응답 거절, 동일 요청 중복 방지, 동시 분석 방지, 분석 중 다른 탭의 원본 수정, 변경한 행동의 별도 보관, 과거 리포트 보존, 소유권, 실패/한도/만료 복구를 검증했다.
- 동일 테스트에서 실제 LLM 어댑터를 가짜 fetch로 실행했다. JSON schema, `store:false`, 출력 상한, 사용량 기록, quota 오류 후 재시도/fallback 없음이 통과했다. 실제 인터넷 호출이나 유료 사용은 없었다.
- `operating-analysis-http-lab.test.mts`: 고정 주소 `127.0.0.1:8095`의 격리 서버에서 미리보기, 동의, 모의 생성, 재요청, 수정된 행동 보관, 다시 읽기, 다운로드, 다른 소유자의 접근 거절, 오래된 자료 거절을 확인했다.
- 브라우저: 가상 데이터로 2개 기간을 직접 입력했다. PC 1280x900와 모바일 390x844에서 전송 확인 창과 리포트를 확인했다. 미동의 시 실행 차단, 고객 반응 포함/제외, 취소, 모의 분석, 행동 직접 수정, 보관함, 새로고침 복원, 브라우저 다운로드 이벤트가 통과했다.
- 모바일 확인 창은 가로 넘침이 없었고(`clientWidth = scrollWidth = 350`), 개선안 영역도 문서 전체 가로 폭 390px 내에 표시됐다.
- TypeScript `--noEmit --incremental false` 및 `git diff --check` 통과.

## 출시 전 남은 검증

1. 운영과 분리된 스테이징의 Supabase/Google 로그인 및 소유권 이전. 이번 분석 저장 경합은 메모리에서 검증했으며 실제 DB 종단 간 검증은 남아 있다.
2. 승인된 가상 사업 데이터와 비용 상한으로 실제 AI 분석. 신규 창업/기존 운영/재방문 사업에서 입력 근거, 수치, 과잉 추정, 실행안 품질과 지연을 평가한다.
3. 실제 PDF/Word/PPT 생성, 렌더링, 다운로드, 재접속 후 내려받기, 생성 실패 복구. 이번 Markdown 개선 리포트 검증과 혼동하지 않는다.
4. 테스트 PG 승인/취소/중복/환불과 권한 반영. 새 분석 기능의 유료 제공 범위와 권한 정책도 출시 전에 확정한다.
5. Cloudflare 런타임의 요청 중단/실행 시간과 작업 복구, 지속 저장, 통합 비용/장애 알림 검증. 자동 정기 리포트 발송은 미구현이다.

실제 AI/PPT/결제 검증 전까지는 유료 플랫폼 전체가 완성됐다고 안내하지 않는다.
