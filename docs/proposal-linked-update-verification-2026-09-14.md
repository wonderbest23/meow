# B2B 제안서 원문 변경 반영 검증

## 결론

가상 B2B 사례에서 원문 가격 변경 → 영향 페이지 비교 → 실제 AI 부분 재작성/원문 검토 → 로컬 계정 저장 → 사용자 승인 → 재접속 → PPT 다운로드 → 이전 내용 복원까지 검증했다.

실제 사용자 사업 원문을 AI로 전송하는 공개 API는 열지 않았다. 이번 승인 범위는 가상 데이터 검증이다. 안전 검토에서 실제 사용자 전송 경로가 보류되어, 공개 API의 generate 명령은 서버에서 503으로 거절하며 환경변수만으로 해제할 수 없다. 운영 배포, 실제 PG 결제, Google OAuth 스테이징 검증은 이번 범위가 아니다.

## 구현

- 페이지 편집과 공통 원문 수정 진입점을 구분한다. 페이지에서 숫자만 바꾸는 것은 공통 사업 조건을 바꾸지 않는다.
- 공통 원문이 바뀌면 저장 당시 원문과 현재 원문을 비교하고 sourceSections로 영향받는 페이지를 찾는다.
- B2B 고객 제안서의 연관 페이지 1~6장을 한 번에 검토한다. 일부만 반영하고 전체가 최신인 것처럼 표시하지 않는다. 사업명 변경 등 6장 초과 변경은 전체 재검토가 필요하다.
- 실제 AI에는 필요한 원문과 해당 페이지의 기본 문안만 전달한다. 수동 편집, 이미지 데이터, 배치 좌표는 전달하지 않는다.
- 새 문안은 원문 검토와 기존 PPT 규격을 통과한 뒤 ready로 보관한다. 자동 반영하지 않는다.
- 비교 화면에서 달라진 제목, 본문 항목, 표 셀을 강조한다. 직접 수정한 페이지는 내 문안 유지/새 문안 교체를 명시적으로 선택한다.
- 내 문안을 유지하면 이전 가격이나 조건이 남을 수 있음을 표시한다. 이미지와 수동 배치는 양쪽 선택 모두 유지한다.
- 소유자/사업/입력/전송 대상에 묶인 해시, 원문 지문, 편집 내용 해시, 버전 CAS로 오래된 결과 반영을 차단한다. JSONB의 키 순서는 내용 변경으로 취급하지 않는다.
- 같은 요청 재전송은 AI를 다시 호출하지 않는다. 사업별 동시에 한 건, 최근 24시간 3건, 누적 30건으로 제한한다. 자동 유료 재시도와 대체 공급자 호출은 하지 않는다.
- 생성/검토의 토큰 상한은 3000/1000, 요청 시간은 60/35초다. 전체 작업은 120초 이후 만료된다. 실패/취소/늦은 응답은 기존 제안서를 바꾸지 않는다.
- 버전 기록은 편집값뿐 아니라 당시 슬라이드/원문/지문을 보관한다. 이전 edit-only 기록도 첫 연동 변경 전에 원래 문서 기준으로 변환한다. 최대 20개이며 큰 기록은 오래된 것부터 줄이고 직전 버전은 유지한다.
- 승인된 편집본은 일반 문서 화면의 PPT 다운로드에도 반영된다. 복원한 과거 버전은 편집기의 버전 지정 다운로드로 받을 수 있다.

## 실제 AI 검증

- 입력: 스크립트가 만든 가상 `온결 스튜디오` 자료만 사용
- 변경: 제품군 1개 기준 제안 가격 150만원 → 180만원
- 갱신: 사업 정의, 제공 범위, 가격과 거래 조건 3장
- 변경하지 않은 9장, 직접 지정한 제목 배치 보존
- 모델: gpt-6-astra
- 생성: 12.95초, 입력 1680 / 출력 722 토큰
- 원문 검토: 2.38초, 입력 1281 / 출력 15 토큰, 문제 지적 없음
- 두 요청 성공, 추가 재시도 없음
- 누적 승인 예산: 5달러. 보수적 예약 상한 누적 4.434125달러, 남은 예약 여유 0.565875달러
- 예약액은 실제 청구액이 아니다. 실제 청구액은 조회하지 않았다. 기존 budget.json을 이어 사용했으며 새 예산으로 초기화하지 않았다.
- 단가 확인: https://developers.openai.com/api/docs/models/gpt-6-astra

## 로컬 통합 검증

운영과 분리된 Supabase 127.0.0.1:55431과 앱 127.0.0.1:8094를 사용했다. 테스트 스크립트에서 실제 AI 응답을 재사용해 로컬 계정에 보관했으며, 브라우저 실행 중 추가 유료 호출은 없다. 문서 이용 권한은 가상 주문으로만 부여했고 실제 결제는 하지 않았다.

1. 승인 전에는 기존 150만원 제안서가 유지됨
2. PC/320/390/768px에서 비교 화면과 수동 문안 선택에 가로 넘침 없음
3. 승인 응답이 유실돼도 서버 반영은 한 번이며 새 버전으로 복구
4. 일반 PPT 다운로드의 해당 3장에 180만원이 있고 150만원은 없음
5. 수동 제목과 native PPT 좌표 보존
6. 버전 복원 시 내용과 당시 원문까지 복원, 승인 버전으로 다시 복원 가능
7. 로그아웃/새 브라우저 세션 로그인/버전 지정 다운로드 성공
8. 잘못된 다운로드 버전 409, 비로그인 타 계정 접근 404, 공개 AI 생성 경로 503

다운로드한 PPT를 LibreOffice로 PDF 변환하고 갱신된 2/5/8페이지를 이미지로 확인했다. Microsoft PowerPoint 앱 자체에서 열어 편집하는 검증은 하지 않았다.

## 남은 출시 조건

1. 실제 사용자 원문 전송에 대한 승인과 화면의 자료 확인/명시적 동의 연결
2. 스테이징의 실제 로그인/문서 권한/AI 요청/프로세스 종료 복구 검증
3. B2B에서 6장 초과 변경의 전체 재생성 버전 병합, 장시간 작업용 durable workflow
4. 검증된 편집 흐름을 다른 업종에 확대하고 업종별 실제 고객 제안서로 품질 확인
5. 이미지 교체/크롭, 복잡한 표 구조 변경, 차트/도형 직접 편집은 별도 단계

현재 원문 변경은 사업계획서 편집 경로를 이용한다. 코치의 공통 가격·비용을 바꿨다면 최신 원문 생성이 선행되어야 한다. 슬라이드에서 가격을 바꾸기만 하면 공통 사업 정보와 재무 계산까지 자동 수정되는 기능은 아니다.
