# 계획서 변경안과 제안서 연결 검증

> 후속 단계에서 동의 기반 실제 OpenAI 생성기와 기본 비활성 Workflow 접수를 연결했다. 아래의 null 런타임과 모의 생성 설명은 최초 단계 기록이다. 실제 AI 결과 및 브라우저 재검증은 [후속 검증 기록](./document-proposal-ai-verification-2026-09-14.md)을 참고한다.

## 이번 단계에서 달라진 점

앞 단계는 사용자가 계획서를 직접 수정하고 최신 조건으로 검토 완료하는 방식이었다. 이번 단계는 새 본문을 별도 초안으로 저장한 뒤 항목별로 비교하고 승인하는 흐름을 추가했다. 실제 AI 생성기는 아직 연결하지 않았다.

1. 제안서 편집기에서 최신 사업 조건을 반영하지 않은 문서 항목을 표시한다.
2. 한 번에 최대 3개 항목을 선택하고 전송 예정 자료를 확인한다.
3. 작성 결과를 기존 문서와 분리해서 저장한다. 응답이 끊겨도 저장된 요청과 초안을 다시 불러온다.
4. 각 항목마다 새 본문으로 교체하거나, 현재 본문을 최신 조건으로 직접 확인한 뒤 유지하도록 선택한다.
5. 선택한 항목 전체를 한 번에 반영한다. 이전 본문은 복원을 위해 남긴다.
6. 계획서 승인만으로 PPT를 바꾸지 않는다. 관련 슬라이드 변경안의 별도 비교와 승인 이후에만 PPT에 반영한다.

잠긴 문서는 자동 갱신 대상으로 선택할 수 없다. 기존 본문이 없는 항목은 유지할 수 없다. 직접 수정한 문서에는 수동 편집 표시와 명시적 처리 선택을 제공한다.

## 데이터와 승인 경계

- 전송 미리보기에는 사업명, 설명, 사업 단계, 공통 조건의 항목·값·근거 구분, 예상 손익 기준, 선택한 기존 본문만 포함한다. 대화 전체와 메시지 식별자는 제외한다.
- 선택 항목 수는 3개, 직렬화된 전송 자료는 30,000자, 응답 본문은 항목당 8,000자로 제한한다.
- 동의는 해당 자료와 전송 대상의 해시에 연결하며 기본 체크하지 않는다.
- 요청 ID를 재사용한 다른 자료 전송을 거절한다. 작업 실행은 저장소의 버전 검사로 한 번만 선점한다.
- 요청은 24시간 내 6회, 누적 30회로 제한한다. 생성 재시도와 자동 복구 호출을 추가하지 않았다.
- 실행 전후와 승인 시 사업 버전 및 선택 원문의 해시를 검사한다. 다른 탭의 원문 변경이 있으면 묶음 전체를 반영하지 않는다.
- 작업 제한 시간은 120초다. 만료, 전송 대상 변경, 유효하지 않은 결과, 취소 후 늦은 완료를 처리한다.
- `documentRefreshRuntime()`과 기존 `proposalRewriteRuntime()`은 null이다. 공개 `document_generate`와 제안서 `generate` API는 503을 반환한다.
- 실제 사용자 자료 전송 연결과 외부 백그라운드 Workflow는 이번 작업에서 열지 않았다. 모의 런타임은 테스트에서만 주입한다.

## 로컬 검증 결과

앱: `http://127.0.0.1:8094`

격리 Supabase: `http://127.0.0.1:55431`

운영 DB, 운영 배포, 실제 Google 로그인, 실제 PG 결제를 사용하지 않았다. 가상 사업과 로컬 테스트 계정, 테스트용 결제 권한을 사용했다.

- 가격 150만원에서 180만원 변경 후 예상 손익을 다시 계산하고 기존 문서/PPT는 유지했다.
- 저장 응답 손실에도 사업 조건은 한 번만 저장됐다. 다른 탭의 미저장 입력을 보존하고 오래된 덮어쓰기를 거절했다.
- 계획서 9개 항목을 3개씩, 모의 생성 3회로 갱신했다. 각 묶음의 승인 전까지 원문이 바뀌지 않았다.
- 첫 생성 응답을 의도적으로 끊었다. 저장된 초안을 재조회했으며 중복 생성은 없었다.
- 관련 PPT 3개 페이지는 별도 모의 재작성 1회 후 명시적 승인으로 반영했다.
- 새로고침, 로그아웃 후 로컬 재로그인, 버전 지정 PPT 다운로드까지 완료했다. 내려받은 파일 내부의 새 가격을 확인했다.
- 320, 390, 768, 1440px에서 가로 넘침을 검사했다. 390px와 1440px의 실제 화면을 육안 확인했다.
- 추가 단위 검사는 소유권, 잠금, 수동 본문 유지, 복원 기록, 중복 실행, 생성 도중 사업 변경, 생성 후 원문 변경, 대상 변경, 만료, 빈 본문 유지 거절, 잘못된 응답, 취소 후 늦은 완료를 다룬다.

전체 회귀 43/43, 추가 문서 갱신 검사, 브라우저 검사, TypeScript 검사를 통과했다. 브라우저 결과와 화면은 `artifacts/document-refresh-20260914/`에 보관한다. 테스트 로그인 정보는 이 폴더에 복사하지 않는다.

유료 AI 호출 0회, 실제 결제 0회다. 기존 검증 비용 원장은 변경하지 않았다. 모의 생성 성공은 실제 AI의 문장 품질이나 운영 환경의 완주 검증을 의미하지 않는다.

## 다음에 남은 것

1. 사용자 동의에 따른 실제 사업 조건·선택 본문·관련 슬라이드 문안의 외부 전송 연결 승인
2. 승인 범위 내 실제 문서 생성 어댑터와 스테이징 백그라운드 실행 연결
3. 추가 비용 승인 후 가상 자료로 실제 생성 품질, 제한 시간, 재접속 복구, PPT 다운로드 검증
4. 스테이징 Google 로그인과 PG 테스트 결제·취소·중복 처리 검증

이번 변경은 B2B 고객 제안서 경로다. 전체 업종에 대한 실제 AI 갱신 품질, 긴 문서 전체 재생성, 이미지 재배치 품질까지 완료한 것으로 표시하지 않는다. 커밋·푸시와 운영 배포는 하지 않았다.
