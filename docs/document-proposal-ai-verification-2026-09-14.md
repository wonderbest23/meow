# 동의 기반 계획서와 PPT 갱신 검증

## 결론과 DB 확인

사용자가 2026-09-14 승인한 자료 전송 범위와 추가 5달러 예산으로, 가상 B2B 사업의 **조건 수정 → 실제 AI 본문 갱신 → 본문 승인 → 실제 AI 관련 PPT 재작성 → 별도 승인 → 저장 → 재접속 → 다운로드**를 확인했다.

사용자의 최종 정정에 따라 `newapp` (`hagzlppubxxzxllsehbr`)이 오늘창업 플랫폼 DB다. 로컬 설정의 프로젝트 참조와 일치한다. 이 DB는 변경하지 않았다. `testapp`의 용도는 확인되지 않았으므로 정지·삭제·재사용하지 않았다.

작업 저장소는 `/Users/juhong/Developer/meow-main`이며 Desktop의 동명 저장소는 수정하지 않았다. 운영 배포, 커밋·푸시, 실제 결제는 실행하지 않았다. 정식 출시 판정은 여전히 보류다.

## 연결한 기능

- 계획서 갱신과 PPT 부분 재작성은 `PROPOSAL_AI_ENABLED=true`, OpenAI 설정, Workflow 바인딩이 모두 있을 때만 접수한다. 기본값과 현재 스테이징 준비 설정은 false다.
- 전송 전에 자료와 대상 모델을 표시하고 동의를 받는다. 입력이나 모델이 바뀌면 기존 동의 해시로 실행하지 않는다. 대화 전체, 이미지, 슬라이드 배치 좌표, 직접 편집한 PPT 문안은 전송하지 않는다.
- 계획서는 선택한 항목만 최소 수정하고 한 번 검토한다. 문서와 PPT 각각 생성 1회, 검토 1회이며 자동 유료 재시도·자동 보정·다른 제공자로 전환하지 않는다.
- 기존 서명된 내부 통로와 Cloudflare Workflow를 재사용한다. Workflow에는 사업 소유자와 작업 식별자만 전달한다. 실제 원문은 실행 시 저장소에서 다시 확인한다.
- 실행 접수 응답이 끊기면 요청을 보관하고 같은 작업 ID로만 재접수한다. 화면을 새로고침해도 접수 확인 버튼이 남는다. 실행 선점 후에는 중복 생성하지 않는다.
- 작성 결과는 검토 대기 초안으로 저장한다. 기존 본문과 PPT는 각각 승인한 뒤에만 바뀐다. 원문 변경·취소·만료·사용 한도·잘못된 출력·검토 실패 시 이전 문서를 유지한다.
- 문서 작업에도 모델과 입출력 토큰 사용량을 저장한다. 원문을 운영 로그에 추가하지 않았다.

## 실제 AI 결과

가상 사업 `온결 스튜디오`의 건당 가격을 150만원에서 180만원으로 변경했다. 가격 관련 본문 1개를 실제 AI로 갱신했다. 나머지 8개 항목은 가격 수치가 없음을 확인하고 명시적으로 검토 완료했다. **9개 항목 전체를 실제 AI로 재작성한 검증은 아니다.**

| 단계 | 시간 | 입력 토큰 | 출력 토큰 |
| --- | ---: | ---: | ---: |
| 계획서 본문 갱신 | 7.60초 | 718 | 143 |
| 본문 검토 | 3.77초 | 740 | 13 |
| 관련 PPT 재작성 | 17.13초 | 1755 | 897 |
| PPT 원문 대조 검토 | 1.90초 | 1375 | 14 |

모델은 `gpt-6-astra`다. 본문 고지와 거래 조건을 보존했고 관련 PPT 3장에 새 가격이 반영됐다. 나머지 9장의 내용과 구성은 변경되지 않았다. 파일 안에 편집 가능한 텍스트와 표로 출력된 새 가격을 검사했다.

추가 승인 5달러를 기존 장부에 한 번만 합산했다. 총 승인 한도는 10달러다. 이번 4회 호출의 보수적 예약 상한은 **2.715975달러**, 이전 호출을 포함한 누적 예약 상한은 **7.1501달러**, 남은 예약 한도는 **2.8499달러**다. 이는 실제 청구액이 아니며 청구액은 조회하지 않았다. [OpenAI 공식 가격표](https://developers.openai.com/api/docs/pricing)를 기준으로 긴 입력과 캐시 쓰기를 포함한 보수적 상한을 사용했다.

## 로컬 브라우저와 파일 검증

앱 `http://127.0.0.1:8094`, Supabase `http://127.0.0.1:55431`만 사용했다. 실제 AI 결과를 정확히 같은 가상 입력에 재사용했으며 브라우저 검사 중 새 유료 호출은 0회다.

- 문서/PPT 각각 실행 접수를 한 번 실패시켰다. 새로고침 후 같은 ID로 재접수했고 각 결과는 한 번만 저장됐다.
- 승인 전에는 150만원인 기존 자료가 유지됐다. 본문을 승인해도 PPT는 그대로였고 PPT 별도 승인 후에만 180만원이 반영됐다.
- 320/390/768/1440px에서 가로 넘침을 검사하고 모바일/PC 비교 화면을 육안 확인했다.
- 로그아웃 후에는 소유 자료에 접근할 수 없고 재로그인 후에는 같은 개정본을 내려받을 수 있었다. 오래된 개정 번호의 다운로드는 거절됐다.
- 내려받은 PPT를 LibreOffice로 PDF 변환해 변경된 2/5/8페이지를 확인했다. 한국어 폰트 설정을 명시해야 한다. 처음 기본 변환에서는 한글 폰트를 찾지 못했으며, 설치된 Malgun Gothic 폰트를 적용한 재변환에서 텍스트와 표 배치를 확인했다. PowerPoint 앱 자체 검증은 하지 않았다.
- 외부 호출을 차단한 회귀 44/44 묶음, 로컬 종합 검사 7/7 그룹, TypeScript, 격리 Next/OpenNext 빌드 및 Wrangler dry-run이 통과했다. 빌드에 환경파일과 비밀키를 포함하지 않았다.

- 실제 AI 입력·결과·예산: `artifacts/document-proposal-ai-20260914/`

`scripts/document-proposal-live.mts`는 기본 실행 시 비용과 요청 분량만 검사한다. 실제 실행에는 추가 승인 옵션이 필요하며 이미 실행한 기록을 발견하면 중복 유료 실행을 거부한다. 예산 장부와 실행 기록을 지워서 재실행하지 않는다.

`scripts/local-document-proposal-ai.test.mts`는 실제 AI 결과를 재사용하는 별도 브라우저 검사다. Workflow 접수는 모의 구현이고 DB 저장과 승인/조회/다운로드는 실제 로컬 경로다. 외부 Cloudflare의 실행·재시작 복구를 검증한 것으로 해석하면 안 된다.
