# 홈페이지 사업 내용 반영 검증

기준일: 2026-09-13. [앞선 저장 검증](./homepage-save-verification-2026-09-13.md)의 다음 단계다.
이번 작업은 사업안에서 만든 홈페이지 초안의 정보가 실제 템플릿에 보이도록 연결하는 범위다.
운영 DB, 유료 AI, 결제, 홈페이지 공개, 커밋과 배포는 실행하지 않았다.

## 구현한 범위

- 10개 홈페이지 템플릿에 사업명, 상품, 고객, 설명, 가격 안내, 문의 버튼을 매핑한다. 첫 생성과 템플릿 변경 모두 같은 생성 함수를 쓴다.
- 원본 템플릿의 모든 텍스트 슬롯을 명시적으로 덮는다. 매핑되지 않은 영문 예시, 실적, 평점, 후기, 가격, 고객사 등은 실제 사업 정보로 남지 않는다.
- 사용하지 않는 후기, 가격표, 채용 목록, 구독 폼과 원본 푸터를 기본 숨김 처리한다. 검색창, 장바구니, 앱 다운로드, 동영상 아이콘 등 기능 없는 진입점도 제거한다.
- 원본 래스터 이미지는 초안의 업종 이미지로 교체한다. 이 이미지는 실제 사업장이나 상품을 검증한 사진이 아니다. 공개 전 사용자 사진으로 교체하거나 사용 적합성을 확인해야 한다.
- 기존에 저장한 홈페이지는 열기만 해서는 바꾸지 않는다. `사업 정보 적용`을 눌러야 갱신하며, 이후 저장해야 서버에 반영된다.
- 자동 생성 기준 정보와 현재 수정본을 비교해 직접 바꾼 글, 빈 문구, 사진, 링크, 크기, 숨김, 섹션 순서를 보존한다. 기준 정보가 없는 이전 저장본은 저장된 덮어쓰기 값을 수동 수정으로 취급한다.
- 템플릿 변경은 선택 후 `이 템플릿 적용`으로 확정한다. 사업 정보는 이어지지만 수동으로 바꾼 문구와 사진, 배치는 초기화된다는 경고를 먼저 표시한다.
- 고객용 선택기에는 사업 홈페이지 10개만 표시한다. 원본 26개 중 로그인, 장바구니, 결제 등 16개 내부 화면을 구현된 기능처럼 선택하게 하지 않는다. 개발용 원본 갤러리와 과거 저장본은 강제로 변경하지 않는다.
- 모바일 사업 초안은 원본 고정 좌표와 별도의 반응형 흐름을 사용한다. 사업명, 설명, 이용 안내, 문의, 사진 순으로 재배치하고 중복 문구, 중복 사진, 빈 폼을 줄인다. 글씨 크기 변경과 클릭 편집도 같은 슬롯에 저장한다.

검증 fixture는 이제 가상 카페의 상품과 고객을 `landingDraftFromPlan`에 넘긴다. 템플릿 예시 문구를 테스트 화면에서 별도로 주입하지 않는다.
브라우저 검증은 운영 비밀키가 없는 메모리 전용 서버와 실제 편집기/저장 API를 사용했다. 로그인된 `/plan/homepage` 전체 경로 또는 Supabase 영속성 검증과는 구별한다.
10개 모두 데이터 매핑 검사를 통과했지만 모든 템플릿의 장문, 모든 이미지 비율, 실제 휴대전화 키보드까지 시각 검증한 것은 아니다. PC 원본은 고정 좌표이므로 긴 문구의 줄바꿈/잘림 검증이 추가로 필요하다.
기존 `scripts/brainwave-mobile.test.tsx`의 Node 단독 실행은 Next 폰트 변환이 없어 `Urbanist is not a function`으로 실행되지 않았다. 이 스크립트를 통과했다고 집계하지 않았다. 실제 Next 서버의 모바일 렌더링은 위 브라우저 검증으로 확인했다.

## 구별해야 할 한계

- `사업 정보 적용`은 현재 홈페이지 초안에 저장된 사업 정보를 재반영한다. 새 대화의 최신 사업안을 기존 홈페이지로 다시 가져오거나 주기적으로 동기화하는 기능은 아니다.
- 저장된 사업 정보라는 사실이 사실 검증 완료를 뜻하지 않는다. AI가 제안한 상품과 고객도 원본 사업안에 들어 있을 수 있다. 제안 가격 표시와 비공개 매출 제외는 유지하지만 공개 전 내용 검토는 필요하다.
- 문의 버튼의 기본 연결 대상은 기존 공개 페이지의 문의 양식이다. 문의 비활성화, 사용자 지정 링크, 공개 후 문의 접수는 별도 전체 경로 검사 대상이다.
- 선택기의 이미지는 원본 디자인 예시이며 생성된 초안과 섹션/사진/문구가 다르다. 모바일은 내용 중심 반응형 표현이므로 원본 PC 화면의 픽셀 단위 복제가 아니다.
- 수동 수정 판별은 현재 템플릿 매핑으로 생성한 기준값과 비교한다. 향후 매핑을 바꿀 때는 기존 생성본의 기준 버전 보존과 마이그레이션 검증이 필요하다.
- 이미지 업로드, 유료 AI 편집, 공개/재공개/롤백, 접근 권한과 결제, 실제 Supabase 동시 저장은 아직 별도 검증이 필요하다.
- 정기 운영 리포트, 기간별 실적 비교, 이전 계획서와 새 리포트 이력은 이번 변경에 포함되지 않는다.

## 다음 순서

1. 아이디어 없음, 이미 운영 중인 사업, 여기서 시작한 사업의 재방문 개선을 각각 같은 사업 ID로 끝까지 점검한다. 기존 자료 보존과 새 수정 반영을 구분한다.
2. 새 대화의 사업안을 기존 홈페이지에 가져오는 명시적 갱신 흐름과 변경 전후 비교를 보완한다. 생성 요청의 프로젝트 중복 연결과 저장 충돌 복구도 함께 검사한다.
3. 지속 개선 리포트의 최소 범위를 확정한다. 실제 결과 입력, 전후 비교, 개선안 선택, 과거 문서 보존, 새 리포트 이력을 구현/검증한다.
4. 스테이징을 마련한 뒤 Google 로그인, 테스트 결제, 실제 PDF/Word/PPT 생성·재다운로드, 이미지 업로드, 홈페이지 공개와 문의 접수를 검증한다.

이번 결과만으로 홈페이지 자동 생성이나 플랫폼 전체를 출시 검증 완료로 표시하지 않는다.
