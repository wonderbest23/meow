# 출시 전 newapp DB 검증

> 후속 완료: 누락된 0027~0030을 기존 자료 보존 확인 후 반영했고, 계정 연결·홈페이지 공개/복원 DB 통합 16/16과 이메일 로그인 브라우저·HTTP 8/8이 통과했다. 아래의 구조 누락·DDL 미실행·다음 적용 순서는 최초 검사 당시 기록이다. [최신 구조 반영과 검증](./prelaunch-lifecycle-verification-2026-09-15.md)

## 대상과 승인

사용자가 `newapp`은 아직 정식 출시 전이며 DB 테스트를 계속해도 된다고 확인했다. `hagzlppubxxzxllsehbr`에 실행별 새 가상 계정 2개만 만들고, 해당 계정에 가상 B2B 사업 자료를 저장했다. 기존 자료를 읽어 시험 데이터로 복사하지 않았다.

- 최종 실행: `2134be3ea86d7ca3`, 외부 요청 72회, 검사 15/15 통과
- 결과: `artifacts/prelaunch-db/2134be3ea86d7ca3/report.json`
- 파일: 같은 폴더의 `reconnected-proposal.pptx`, `operating-report.md`
- 최초 실행 `8d4c0c6360f28aff`도 15/15 통과했다. 렌더링에서 테스트 좌표의 제목/소제목 겹침을 확인해 제목 y를 1.2에서 1.9로 조정한 뒤 새 계정으로 전체 검증을 반복했다. 제품의 자유 배치가 겹침을 자동 방지한다는 뜻은 아니다.
- 두 실행 합계 가상 계정 4개와 가상 사업 4개를 후속 확인을 위해 보관했다. 각 실행의 두 번째 계정은 사업 목록이 비어 있다. 총 외부 요청은 144회다.
- 기존 자료 삭제 0건, 스키마 변경 0건, AI 호출 0회, 결제 0회. AI 예산 장부도 동일하다.
- `.env.local`의 DB 자격증명만 사용했으며 파일 자체를 바꾸지 않았다. 비밀번호·세션·비밀키는 결과 파일에 남기지 않았다.
- 외부 호출 없는 회귀 45/45, TypeScript, `git diff --check` 통과. 기존 로컬/스테이징 보호 정책도 그대로 검사했다.
- 최종 PPTX는 LibreOffice에서 12쪽 PDF로 열리는 것을 확인했고, 변경된 첫 장을 렌더링해 제목과 소제목의 비겹침을 확인했다. `reconnected-proposal.pdf`와 `slide-01.png`를 같은 결과 폴더에 보관했다. Microsoft PowerPoint 자체 검증이나 전체 슬라이드 디자인 품질 판정은 아니다.

## 확인한 동작

| 범위 | 결과 |
| --- | --- |
| Supabase 인증 | 가상 이메일 계정 생성/로그인, 잘못된 비밀번호 거부, 세션 갱신, 로그아웃/재로그인 |
| 계정 격리 | 다른 계정으로 제안서·실적 자료 접근 시 404, 사용자 JWT로 DB 원문 읽기와 수정 차단 |
| B2B 자료 | 계획서 9개 항목과 제안서 12장 저장, DB 왕복 후 원문 지문 일치 |
| 편집 저장 | 제목·배치 저장, 같은 요청 재전송 시 중복 버전 없음, 오래된 탭 저장 거부 |
| 동시 저장 | 같은 버전의 두 수정 중 하나만 성공, 다른 수정은 충돌 반환 |
| 버전 복원 | 2번 편집본의 제목과 배치를 4번 버전으로 복원, 과거 이력 유지 |
| 기간 실적 | 두 기간 기록, 매출 차이 계산, 미입력과 0 구분, 0 대비 증감률 미계산 |
| 리포트 보관 | 같은 요청으로 중복 보관되지 않음, 실적 수정 후에도 보관 당시 수치 유지 및 오래된 보고서 판별 |
| 재접속 | 재로그인한 사용자 ID로 같은 owner hash를 구하고 문서·편집·기록 전체를 동일하게 읽음 |
| 파일 생성 | 다시 읽은 편집본으로 실제 PPTX 생성, 12장과 저장한 제목을 내부 XML에서 확인 |
| 여러 사업 | 같은 계정의 두 번째 가상 사업 추가 후 첫 사업의 문서와 기록 보존 |

**서비스 함수와 외부 DB/API 검사**다. 브라우저 로그인 쿠키, Google OAuth, PG sandbox, Cloudflare Workflow, HTTP 다운로드 권한은 이번 검사의 범위가 아니다. PPT는 합성 생성 결과를 편집·저장한 것이며 새 유료 AI 생성 검사가 아니다. 운영 리포트는 사용자 기록과 비교를 보관한 것으로 AI 분석 품질을 검증한 것이 아니다.

## 실제 발견한 미반영 구조

사용자 자료를 조회하지 않고 서비스 역할의 PostgREST OpenAPI 구조를 확인했다.

| 마이그레이션 | 없는 구조 | 영향을 받는 흐름 |
| --- | --- | --- |
| 0027 | `plan_owner_claims`, `commit_plan_state`, `claim_plan_state` | 비회원 사업을 계정으로 옮기기, 이전된 비회원의 오래된 저장 요청 차단 |
| 0028 | `plan_owner_claims.legacy_completed_at` | 기존 프로젝트 이전이 중단된 뒤 재시도 추적 |
| 0029 | `llm_usage.model/elapsed_ms/failure_code`, `admin_generation_jobs` | 단계별 생성 장애·처리시간 운영 조회 |
| 0030 | `published_slug`, `source_updated_at`, `ensure_plan_project`, `publish_landing_snapshot`, `rollback_landing_snapshot` | 홈페이지 프로젝트 중복 방지, 초안·공개본 분리, 원자적 공개·복원 |

검증 프로세스 안에서만 `PLAN_ACCOUNT_LINKING_ENABLED=false`로 기존 CAS 저장 경로를 사용했다. 이를 자료 이전 기능 통과로 계산하지 않는다. 서버 설정과 배포 정책은 변경하지 않았다.

## 다음 적용 순서

1. 현재 스키마 정의와 마이그레이션 이력을 보관하고, 0030의 기존 공개 슬러그 중복 및 한 사업에 연결된 프로젝트 중복을 읽기 전용으로 확인한다. 중복 발견 시 자동 삭제하거나 임의 병합하지 않는다.
2. 누락된 0027~0030만 대상과 변경 SQL을 확인한 뒤 반영한다. DB 초기화나 0001부터의 무조건 재실행은 하지 않는다.
3. 별도 가상 계정으로 비회원 자료 이전의 중복·동시 로그인·오래된 탭 방어와 홈페이지 공개·복원을 검증한다.
4. 이후 보호된 테스트 앱에서 Google 로그인, PG sandbox, Workflow 재시작·다운로드·알림 수신을 확인한다.

출시 준비 완료 판정은 아직 `false`다. 이 DB를 출시 전 검사에 쓰는 승인과 인터넷 공개·실제 결제 승인은 구분한다.

## 재실행 안전장치

`scripts/prelaunch-db.test.mts`는 정확한 `newapp` URL과 `--allow-prelaunch-newapp` 플래그를 함께 요구한다. 요청 범위를 이번 실행의 이메일·owner hash·plan ID 접두사로 제한하며, 전체 테이블 조회·다른 테이블 변경·RPC·DELETE·리다이렉트·다른 호스트를 거절한다. 최대 요청 수는 240회다. 별도 로컬 검사 및 스테이징 배포 차단 정책을 풀지 않았다.

```sh
node --import tsx scripts/prelaunch-db-safety.test.ts
node --import tsx scripts/prelaunch-db.test.mts --allow-prelaunch-newapp
```

매 실행마다 새로운 가상 계정을 만든다. 기존 검사 계정의 비밀번호는 저장하지 않으며 후속 확인은 별도 승인된 관리 경로로 수행한다. `artifacts/`는 Git 제외 상태다.
