## 실수 유실 상세

**(1) 영향 섹션이 값을 못 받는 10건** — 답을 저장하고 그 섹션을 다시 써도 내용이 바뀌지 않는다.

```
promo_budget    → summary/executive          (marketing.budget 미수신)
message         → summary/executive          (marketing.message 미수신)
funding_sources → financials/financing, summary/executive
use_of_funds    → financials/assets, summary/executive
competitor_notes→ market/swot, summary/executive
why_us          → overview/structure
who_works       → summary/executive
monthly_volume  → strategy/distribution
growth_ceiling  → summary/executive
```
※ `differentiator → market/competitors` 는 `competition.differentiator` 로 수신하므로 정상(오탐 제외).

**(2) 4차 테스트가 이 문제를 못 잡은 이유**: 4차 테스트의 판정이 "같은 그룹(`marketing.*`)의 필드를 하나라도 받으면 통과"로 느슨했다. 엄격 판정(정확히 그 필드)으로 재측정하니 10건이 드러났다. **테스트가 관대해서 통과한 것이지 문제가 없던 것이 아니다.**

**(3) 30개 플랜 절단** — `plan-server-store.ts:75` `plans.slice(0, 30)` 이 **읽기·쓰기 정규화 양쪽**에 걸려 있고, `mergeStates` 는 `createdAt` 오름차순 정렬 → 31번째부터 **최신 플랜이 잘린다.** 현재 계정 플랜 24개(한도까지 6개).
※ 정적 분석. 계정에 31개를 만드는 파괴적 테스트는 하지 않았다.

# 역질문 평가

## 실제 슬롯 선택 (10개 사업 전수)

```
C-class   1R customer, problem, solution, classPrice
          2R seatsPerClass, classesPerMonth, venueType, materialCost
D-commerce 1R customer, problem, solution, aov
          2R monthlyVisitors, conversionRate, cogs, differentiator
나머지 8개 1R customer, problem, solution, unitPrice
          2R monthlyVolume, unitCost, fixedTotal, differentiator   ← 8개 전부 동일
```

**중요한 단서**: 슬롯은 같아도 **문장은 LLM이 사업에 맞게 다시 씁니다.** SaaS 실측:

> "음식점 사장님 한 분이 이 서비스를 **한 달 쓰는 데** 얼마를 내게 하고 싶으세요?" (= unitPrice)
> "처음 시작하고 몇 달 동안은 **몇 명의 음식점 사장님이 구독**할 것 같나요?" (= monthlyVolume)

즉 사용자 눈에는 "우리 사업에 맞는 질문"으로 보인다. 문제는 **묻는 개념의 종류가 4개로 고정**되어 있다는 것이다.

## 안 묻는 것

`ownerExperience` · `initialInvestment` · `salesChannel` 은 **2라운드(최대 8문항) 안에 절대 나오지 않는다** — blocking 8개가 자리를 다 채우기 때문. `important` 등급이라 순위에서 밀린다.

그런데 Reviewer 는 나중에 "대표자 관련 경력이 제시되지 않음"을 지적한다. **묻지 않고 나중에 없다고 지적하는 닫힌 고리**가 있다.

## gapHints 17% 폐기

Analyzer 는 **모든 팩의 슬롯 목록**을 보고 힌트를 주는데, Gap 엔진은 **선택된 팩의 슬롯만** 쓴다. 52개 중 9개(17%)가 버려진다.
가장 심한 A-cafe: 6개 중 5개 폐기(`aov`·`monthlyVisitors`·`cogs`·`fixedOps`·`venueType` — 전부 commerce/class 팩 소속).

# 질문팩 적합성 — "전용 팩이 없으면 무엇이 나빠지는가"

단순히 "팩을 추가해야 한다"고 결론내지 않고, **본문에 무엇이 나타나는지**까지 추적했다.

## 전용 팩이 있을 때 (C-class, 실제 출력)

> "월 판매량 38건은 **정원 6명 × 월 8회 × 예상 평균 참석률 80%**를 곱해 산출한 계획값이며 …

## H-content(광고·협찬을 unit_sale 로) 실제 출력

> "유료 콘텐츠 판매는 사업 설명에 포함된 수익 구조이지만 **이번 12개월 예측에는 반영하지 않았고**, 광고·제휴 수익만으로 재무 계획을 구성했다."

## 결론 (중요)

**팩 부재는 "틀린 문서"를 만들지 않는다. "얕은 재무 모델 + 정직한 한계 고지"를 만든다.**

연결 고리:
```
전용 팩 부재
→ 모델 고유 변수(churn·좌석회전·GMV·조회수)를 물을 슬롯이 없음
→ FinancialInputs 가 단가×수량으로 축소
→ Writer 가 그 축소를 감지하고 "반영하지 않았다"고 명시
→ Reviewer 가 "이탈률 미반영", "1인 운영 가능성 미확인" 등으로 재지적
→ 보완질문이 그 문제를 받으면 **owner_pay·fixed_total 로 오매핑**(§Reviewer→보완질문)
```

10개 중 **반복적으로 품질에 영향을 준 것은 subscription(F) · commission(J) · seat(A) · ad_content(H) 4종**. `service_hour`(B·G)는 단가×건수로 충분히 표현되어 실질 손해가 작았다.

→ 향후 팩 추가 후보: **subscription · seat · commission** (ad_content 는 건당 협찬으로 근사 가능). **12개 전부는 근거 없음.**

| 5 | 마케팅 실행 계획 구체성 부족 | **PARTIAL** | 맞지만 "구체성 부족"은 다소 일반적. 2회 모두 나옴 |
| 6 | 손익분기 예상 시점과 계산모델 간 5개월 격차 | **TRUE POSITIVE** | 사용자 답변 6개월 vs 계산 1개월차 — 정확한 지적 |
| 7 | 공식 시장 근거 0건 (deterministic) | **TRUE POSITIVE (그러나 해결 불가)** | 사실이지만 §시장조사 때문에 사용자가 고칠 수 없음 |
| 8 | 아직 정하지 않은 항목 1개 (deterministic) | **LOW VALUE** | 항상 나오고, 보완질문으로 이어지지 않음(아래) |

**FALSE POSITIVE 0건.** (3차에서 발견된 `knows_breakeven` 오탐은 4차 수정 후 재현되지 않음 — 3회 모두 `fact_safety` 0건.)

**놓친 문제**: 12개월 예측이 물리 상한을 넘는 문제(§재무 P1)는 Reviewer 도 못 잡는다 — 검사 자체가 1개월만 본다.

**deterministic ↔ AI 중복**: 0건 (병합 규칙이 작동).

**Reviewer 가 없는 사실을 근거로 지적**: 0건.

## 실행 안정성

**3회 중 1회 실패**(`source: deterministic`, `score: -1`, 129초). 3차에서 두 번 고쳤는데도(상한 16,000 + 잘린 JSON 복구) 부하 상황에서 다시 실패했다. 실패 시 확정 문제 2건만 표시되어 **사용자는 "AI 검토를 완료하지 못했다"는 빈약한 결과를 본다.**

## P2 — 핵심축 미확정은 항상 질문으로 이어지지 않는다

```
answerResolution(["problem.statement"])  → manual_edit  slots=[]
answerResolution(["customer.target"])    → manual_edit  slots=[]
answerResolution(["solution.mainOffer"]) → manual_edit  slots=[]
answerResolution(["revenue.unitPrice"])  → manual_edit  slots=[]
```
`context.unknowns` 는 핵심축을 **점 표기 경로**(`problem.statement`)로 넣는데, 4차에서 넣은 별칭표는 **분석 슬롯 id**(`problem`·`classPrice`)만 다룬다.
→ "아직 정하지 않은 항목이 N개 있습니다" issue 는 **핵심축이 비었을 때 보완질문을 제공하지 못한다.**
→ 운영 실측에서 재현: 3회 실행 모두 이 issue 가 `manual_edit` 로 나왔다.

## 매핑 일관성

같은 문서 두 실행에서 사실상 같은 문제("마케팅 실행 계획 구체성 부족")가 한 번은 `manual_edit`, 한 번은 `answer` 로 갈렸다. **키워드 정규식이 Reviewer 의 문장 표현에 의존**하기 때문이다.

# 보완 루프 실측

> **범위 조정 고지**: 사양은 서로 다른 issue 5건의 라이브 루프를 요구했다. 이번 감사에서는 **라이브 1건(4차에서 완주) + 정적 전수 감사(14종 issue × 매핑 × 영향섹션 수신 여부)** 로 대체했다. 이유: (a) 라이브 루프 1건이 재생성 3섹션 + 재검토로 약 5분·재생성 쿼터 3회를 쓴다, (b) 감사 중 계정에 임시 플랜을 쓰는 동작이 차단되어 통제된 문서로는 루프를 돌릴 수 없었다, (c) 정적 감사가 라이브보다 **더 많은 결함(10건)** 을 드러냈다.

## 라이브 1건 (4차, 마케팅) — 재확인

```
Reviewer "판매 목표는 있는데 고객을 데려올 방법이 없습니다"
→ [답변 추가하기] → 질문 2개(기존 137개 질문 문장 그대로)
→ 인스타그램·지역 커뮤니티 / 월 15만원 저장 + has_promo_budget 게이트 자동 설정
→ 영향 3섹션만 재생성 (15개 중 3개만 변경, 12개 해시 불변)
→ 재생성 본문에 "| 홍보 채널 | 지역 커뮤니티·맘카페, 인스타그램 |" 반영
→ Review 자동 stale
```
**루프 자체는 설계대로 완주한다.**

## 정적 전수 (5종 이상)

| issue 종류 | 매핑 | 답 저장 | 영향 섹션이 값 수신 |
|---|---|---|---|
| 마케팅(채널) | `promo_channels`+`message` ✓ | ✓ | **부분** — message 가 executive 미수신 |
| 차별점 | `differentiator`+`competitor_notes` ✓ | ✓ | **부분** — competitor_notes 가 swot·executive 미수신 |

| 운영 capacity | `growth_ceiling`+`owner_hours` ✓ | ✓ | **부분** — executive 미수신 |

**5종 모두 매핑과 저장은 정상, 재생성 반영은 부분적.**

# 현재 기준 출시 가능 여부

## 판매 가능하다 — 단, 두 가지 조건부

**가능한 이유** (실측 근거):
- 71개 섹션에서 범용문장 **0회**. 이건 대부분의 AI 사업계획서 서비스가 못 하는 수준이다.
- 49,277자 전체 문서에서 **숫자 환각 0건**. 의심 9건을 전수 추적해 전부 정당함을 확인했다.
- 고객이 `unknown` 인 문서가 고객을 **지어내지 않고** "추가 정의 필요"로 남긴다.
- 재무 인용값이 계산 엔진과 **완전 일치**한다.
- 모든 실패가 안전하게 저하된다(문서를 잃는 경로는 30플랜 케이스 하나뿐).

**조건 1 — 지금 당장**: "**공식 시장자료 자동 조사**"를 기능으로 표시·광고하고 있다면 **내려야 한다.** 한 번도 작동한 적이 없다. Reviewer 도 매번 그 버튼을 권하므로 사용자는 반드시 실패를 겪는다.

**조건 2 — 지금 당장**: Reviewer 화면의 **큰 점수 숫자**는 근거가 없다(같은 문서 64↔74). 점수를 빼거나 작게 하고 issue 목록을 주인공으로 두어야 한다.

# 반드시 고칠 것

1. **P0-1 시장근거 검색** — `json_object` 와 `web_search` 를 같이 쓸 수 없다. 구조화 출력을 포기하고 후처리 파싱하거나, 검색과 구조화를 2단계로 나눠야 한다. **2차 작업 전체가 이것 위에 서 있다.**
2. **P1-3 `owner_pay`** — 재무 엔진이 읽지 않는 칸을 보완질문의 답으로 받고 있다. 답해도 아무것도 안 바뀌는 루프는 신뢰를 깎는다.
3. **P1-5 영향 섹션 미수신 10건** — "다시 작성"이 아무것도 바꾸지 않는 경우가 절반이다.
4. **P1-4 30플랜 절단** — 한도까지 6개 남았다. 발생하면 복구 불가.
5. **P2-1 점수 강조 완화** — 코드 변경 없이 UI만으로 가능하다.

# 최종 질문 5개

## 1. 실제 유료 사용자에게 판매해도 될 수준인가?

**문서 품질 기준으로는 예.** 71섹션 범용문장 0회, 49,277자 환각 0건, 미확정을 지어내지 않음, 재무 인용값 전부 엔진 일치 — 이건 실측이고, 상용 수준이다.

**단 두 가지를 지금 고치지 않고 팔면 안 된다**: (a) "공식 시장자료" 기능 표시 — 한 번도 작동한 적이 없다. (b) Reviewer 의 큰 점수 숫자 — 같은 문서에서 12점 흔들린다.

## 2. 지금 가장 큰 품질 병목은?

**시장근거 검색의 완전 고장.** 100점 중 시장 분석 10점에서 8점을 잃고 있고, 2차에 들인 통합 작업 전체가 실행된 적이 없다. 두 번째는 재무 모델 적합성(capacity·owner_pay·모델별 산식).

## 3. 더 많은 질문 / 더 좋은 Writer / 더 좋은 재무모델 / 이미 충분?

**Writer 는 이미 충분하다** — 20점 중 17점. 여기에 더 투자할 이유가 이번 측정에는 없다.
**질문 수도 충분하다** — 8문항으로 재무 6변수를 다 받는다. 문제는 *수*가 아니라 *종류*다.
**재무모델이 다음 병목이다** — 단 P0을 먼저 고친 뒤다.

## 4. 새 기능 개발 vs 안정화?

**안정화.** 근거: 4차까지 만든 기능 중 하나(시장근거)가 **한 번도 작동한 적이 없고**, Reviewer 는 **3회 중 1회 실패**하며, 보완 루프의 **53%가 값을 전달하지 못한다**. 이 상태에서 5차 기능을 얹으면 "있는데 안 되는 기능"이 하나 더 늘 뿐이다.

이번 감사가 드러낸 패턴은 일관된다 — **2차 지표 유실, 3차 false positive, 4차 값 미도달, 그리고 지금 발견한 10건.** 매번 "만들었다"와 "실제로 흐른다" 사이가 벌어졌다. 다음 단계는 만드는 것이 아니라 **흐르는지 확인하는 것**이다.

## 5. 다음 한 가지만 허용된다면?

**공식 시장근거 검색 복구(NEXT 1).**

이유: (a) 유일한 P0다. (b) 고장 원인이 로그로 확정됐고 수정 범위가 좁다. (c) 이미 만들어 둔 2차 결합 코드·인용 검증·Reviewer 연동이 전부 그 위에서 대기 중이라, 하나 고치면 여러 개가 동시에 살아난다. (d) 사용자가 "근거 있는 사업계획서"라는 약속을 실제로 받게 된다.
