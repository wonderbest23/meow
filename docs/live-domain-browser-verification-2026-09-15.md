# 실제 도메인 브라우저 검증

> 후속: 같은 QA 사업의 저장값을 읽기 전용으로 확인해 기존 설문 키와 대화형 사업안 필드의 불일치를 재현했다. 로컬 홈페이지 연결과 PPT 제공 중지 안내·상태 조회를 보완하고 회귀 49/49, 격리 브라우저 검사를 통과했다. 아직 실제 도메인에 배포하지 않았다. [수정 및 검증 결과](./live-handoff-fixes-2026-09-15.md)

## 범위와 판단

사용자의 요청에 따라 `https://oneulstart.com`을 실제 인앱 브라우저에서 조작했다. 스테이징 설정 완료를 기다리지 않고 현재 배포본의 계정, 저장된 QA 사업, 문서 복원, 파일 내려받기, 새 대화 진입, 홈페이지 연결을 확인했다.

현재 브라우저는 이미 로그인된 상태였다. 따라서 **기존 로그인 세션 유지와 계정 자료 읽기는 확인했지만, Google 신규 로그인이나 비회원 자료 이전을 새로 실행한 결과는 아니다.** 기존 계정에서 로그아웃하지 않았다. 기존 사업 내용은 수동 수정하지 않았으며 새 대화에서 메시지를 전송하지 않았다. 결제, 유료 AI 생성, PPT 재생성, 홈페이지 공개, OAuth 설정 변경, 운영 배포는 실행하지 않았다.

## 실제 배포본의 미완료·불일치

### PPT

- 홈페이지와 내려받기 메뉴 모두 `PPT 제공 준비 중`으로 표시된다.
- 이 QA 사업에는 `검토 결과를 읽지 못했어요. 저장된 슬라이드 초안이 있어요. 다시 시도하면 검토부터 이어갑니다`라는 상태가 남아 있다.
- 화면 문의 번호는 `727ee46b`다.
- 하지만 PPT 버튼이 비활성이므로 이 화면에서는 안내된 재시도를 실행할 수 없다.

따라서 실제 PPT 생성/재시도/다운로드는 통과하지 않았다. 기능 활성화 전에 기존 실패 작업의 안전한 복구 경로와 사용자 안내를 맞춰야 한다. 현재 배포본의 이 상태와 로컬·비공개 스테이징의 보강 코드를 구분한다.

### 완성 사업에서 홈페이지로 연결

- 같은 QA 사업의 요약에는 주요 고객과 제공 상품이 표시되고 문서는 `9 / 9 항목` 완료 상태다.
- `/plan/homepage`로 진입하면 다음 필수 내용이 부족하다는 화면에서 멈춘다.
  - `상품·서비스 › 가장 대표적인 상품·서비스`
  - `시장 세그먼트 › 가장 먼저 공략할 그룹`
- 따라서 이번 실제 도메인 검사에서는 홈페이지 편집/저장/공개까지 진입하지 못했다.

문서 완료 조건과 홈페이지 입력 조건 사이의 연결을 확인해야 한다. 요약에 있는 값을 홈페이지 입력으로 어떻게 전달하는지, 현재 배포본과 보강 코드가 일치하는지부터 확인하고 같은 QA 사업으로 다시 검사한다. 현재 관측만으로 정확한 서버 원인을 단정하지 않는다.

1. 같은 QA 사업의 홈페이지 준비 조건 불일치를 재현하고 해결한 뒤 편집 → 저장 → 새 탭 복원을 검증한다.
